### 0.2 术语表（唯一写法，禁止同义替换）

| 术语 | 符号 / 标识符 | 定义 |
|---|---|---|
| 数值步长 | `h1` | `h1 = R * dt`，RK4 积分步长（无量纲时间） |
| 尺度系数 | `R` | 变尺度系数；检测时 `R = omega` |
| 载波角频率 | `omega` | 待测信号角频率，rad/s；`omega = 2π * f0` |
| 工作点 | `lam0` | 内驱幅值，系统处于混沌态 |
| 等效阈值 | `lam_c` | 混沌→大尺度周期的临界值，参考值 `0.7335` |
| 判态统计量 | `pstd` | Poincaré 截面点集的标准差 |
| 单振子 | `osc` | 一路 Duffing 积分器实例 |
| 相位阵列 | `bank` | `N_BETA` 个 `osc`，共享同一输入序列，初相不同 |
| 帧 | `frame` | 一次判决所需的最短样本块，`FRAME_N` 个样本 |
| 帧号 | `frame_id` | 单调递增整数，用于包重组、日志与上位机对齐 |
| 输入样本 | `u` | 待测信号采样值，单位与 `lam0` 同为归一化策动力；固件中为 Q6.12 |
| 频率提示 | `w_hint` | 头包携带的发送端 `omega`，**仅供联调旁路**，不作判决依据 |
| 判决门限 | `q_th` | `pstd < q_th` 判为「检测到目标」 |
| 输入电平 | `peak` | 一帧内 `max(u) - min(u)`，用于判输入静默/断线，与 `pstd` 无关 |
| 每样本 SNR | `SNR_E` | `10lg((A²/2)/σ²)`，每样本能量比。与「力口径 SNR」（按 `lam` 归一）差 `10lg h1`，本链路 **−17 dB**；A6 的 −7.4 dB 是力口径。**引用 SNR 必须带口径** |

**`u` 里没有策动力**：接收序列 = 信号 + 噪声，`lam0·cos τ` 由 §4.4 的 `drv()` 在积分内产生，**不进 `u`**。这条对向量导出（§9.1）与下行联调（§8.4）同样成立。

**禁止使用的写法**：`ν`（旧称，等于 `omega/R`，代码中不得出现）、`simulate`（内核函数名已统一为 `duffing_step`）、`阈值 0.73`（必须写 `0.7335` 并注明来源）、`alpha` 单指相位插值权重（相位相关量一律写 `ph` / `alpha_q30`，避免与噪声谱指数 `alpha` 混用）、把 `lam0·cos τ` 混进 `u`（等于把 `lam0` 算两遍，见 §4.4 禁止 3）。

## 1. 项目目标与功能边界

### 1.1 目标（全部可判定）

| ID | 目标 | 判定标准 |
|---|---|---|
| G1 | 在 ESP32 上以 Q6.12 定点实时积分 Duffing 振子 | 单步耗时 p95 ≤ 8 μs `[SPEC]` |
| G2 | 对一帧样本输出「有/无目标」二值判决 | 与 Python 参考实现判决一致率 ≥ 99% `[SPEC]` |
| G3 | 三相位阵列覆盖初相盲区 | `theta` 全周内 Pd ≥ 0.85 @ SNR −7.4 dB `[SPEC]`，依据 `[LK]` |
| G4 | 控制虚警 | 纯噪声 200 帧 Pfa ≤ 0.05 `[SPEC]` |
| G5 | 内存不随帧长增长 | heap 峰值 ≤ 64 KB `[SPEC]` |
| G6 | 连续运行 24 h 不复位、无溢出累计 | 溢出计数增量 = 0 `[TODO]` |

### 1.2 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 扫 R / 频率盲测 | 固件 v1 只用已知 `R`。**上位机已实现**（`analyze(mode="auto")`：FFT 初值 + 两级细扫），PC 端 0.92 s/帧（重构前 3.6 s），移植代价见 §11.4 |
| 目标初相 `theta` 估计 | v1 只判决。**上位机已实现** `estimate_amp()`（4 相位 × 45 点 `lambda*` 扫描），仅 `detected` 时执行，PC 端约 2.6 s |
| 幅度 `gamma` 估计 | 同上 |
| 无线传输 | 检测期间必须关闭 RF，见 §2.4。联调走 UART（§8.4），不走 WiFi |
| 多目标分辨 | 单频单目标假设 |
| 浮点积分路径 | 定点为唯一路径，不存在运行时切换 |

### 1.3 端到端判据链

```
样本 u[n] → duffing_step() → Poincaré 点 x_k → pstd → 与 q_th 比较 → 0/1
```

### 1.4 上位机参考实现 ↔ 固件模块

`tools/` 下的双端脚本是固件的**对照基准** `[APP]`。同一件事实现在两侧，行为必须一致。

| 环节 | 上位机实现 | 固件对应 | 一致性要求 |
|---|---|---|---|
| 信号与噪声生成 | `link_proto.make_frame()` | 传感器 + `SELF_TEST` DAC 注入 | 仅用于生成向量与自检，固件不生成噪声 |
| 分帧发送 | `split_frame()`，`CHUNK=1024` | `link_ingest`（下行接收） | 包格式逐字节一致，§8.4 |
| 帧重组 | `FrameBuf` | `link_ingest` | 重复包丢弃、缺包补零、超时丢弃，三条必须同 |
| 判决 | `analyze()` → `pstd_array()` | `detector` | 同一 `betas` 顺序、同一 `burn_frac`、同一取 `min` |
| 扫 R（v2） | `fft_guess()` + `scan_R()` | 未实现 | §11.4 |
| 估幅（v2） | `estimate_amp()` | 未实现 | 仅 `detected` 时执行 |
| 参数热更新 | 主线程 100 ms 刷新 `self.cur`，工作线程每帧读 | NVS / 命令，**帧边界生效** | §5.4 |

**初始化顺序**（两侧一一对应；不要先建任务后建缓冲）：

| 步 | 上位机（`RxApp`） | 固件（`app_main`） |
|---|---|---|
| 1 | 建 `Tk` 与控件，读默认参数 | 读 NVS 配置，按 §10.4 校验 |
| 2 | `_refresh_derived()` 刷派生量提示（`f0`、周期数、R 模式说明） | 由 §3.1 常量算 `h1`/`ph_inc`/`frame_n`，`static_assert` |
| 3 | `start()`：先建 `stop_evt` 与参数快照，再起线程 | `ovf_cnt=0`、自检内存、建 ringbuf |
| 4 | 起 `_recv`（收包装配）与 `_worker`（判决）两个线程 | 起 `acq_task`（核 0）与 `proc_task`（核 1） |
| 5 | `_drain()` 每 100 ms 取结果 → 画图 / 刷状态条 | `uplink` 每帧上报 + `TRIG` |
| 6 | **无此环节**：靠人工先跑纯噪声估门限 | `CALIB` 采 20 帧标定 `q_th`（§5.3） |

第 6 步是两侧唯一的结构差异：上位机是离线工具，没有现场标定环节；固件必须自带，否则 `q_th` 只能是仿真值（`[TODO]`）。

## 2. 硬件与外设接口

### 2.1 最小系统

| 项 | 规格 | 备注 |
|---|---|---|
| 模组 | ESP32-WROOM-32（Xtensa LX6 双核，240 MHz） | ESP32-S3 亦可，需改引脚宏 |
| Flash | ≥ 4 MB | 固件 < 300 KB |
| 晶振 | 40 MHz | 采样率精度的基准 |
| 供电 | 5 V / 500 mA，LDO 3.3 V | 纹波 < 10 mV，见 §2.4 |
| 传感器 | 磁通门 / 感应线圈，输出模拟电压 | 需前置放大至 0–3.0 V |
| 串口 | CP2102 / CH340 | 115200 8N1；回放联调用 460800，见 §8.4 |

**前置增益的标定目标**：本规格全部数值（`A = 0.02`、门限 `q_th`、`lam_eff` 余量 0.0065）都在「归一化策动力」单位下，`[APP]` 的噪声口径是每样本 `sigma·sqrt(h1) = 7.07e-3`，折 Q6.12 为 **29 LSB**。因此前置放大应标定到「无目标时背景噪声 RMS ≈ 29 LSB」，`A = 0.0199` 对应 **82 LSB**。增益偏低会让 `A` 变小、`lam_eff` 过不了阈值（表现为「怎么都判不出」）；偏高则噪声吃掉动态范围。**这是 A5/A6 不达标最常见的原因，先查增益再查算法。**

### 2.2 引脚分配

| 信号 | GPIO | 复用 | 方向 | 约束 |
|---|---|---|---|---|
| `ADC_IN` | 34 | ADC1_CH6 | 输入 | **仅输入脚**，无内部上下拉 |
| `ADC_AUX` | 35 | ADC1_CH7 | 输入 | 备用/参考通道，v1 未用 |
| `SELF_TEST` | 25 | DAC1 | 输出 | 注入自检正弦，用于 §9.3 A3 |
| `TRIG` | 4 | GPIO | 输出 | 判决为「有」时拉高 100 ms |
| `LED` | 2 | GPIO | 输出 | 板载；心跳 1 Hz / 报警常亮 |
| `UART_TX` | 1 | U0TXD | 输出 | 日志与二进制上报 |
| `UART_RX` | 3 | U0RXD | 输入 | 命令注入 |
| `BOOT` | 0 | strapping | 输入 | 烧录，运行时勿拉低 |

外部 ADC 变体（`ADC_SOURCE=ADS1256`，SPI）：

| 信号 | GPIO | 约束 |
|---|---|---|
| `SPI_SCK` | 18 | — |
| `SPI_MISO` | 19 | — |
| `SPI_MOSI` | 23 | — |
| `SPI_CS` | 5 | strapping 脚，上电需为高 |
| `DRDY` | 27 | 下降沿中断 |
| `RESET` | 26 | — |

**两套引脚互斥**：`ADC_IN`(34) 与 SPI 组不可同时启用，由编译期 `static_assert` 保证。

### 2.3 禁止使用的引脚

| GPIO | 原因 |
|---|---|
| 6–11 | 接内部 SPI Flash，占用即无法启动 |
| 12–15 | strapping，上电电平影响启动模式 |
| 16、17 | 部分模组接 PSRAM |
| 0、2、5 | strapping；仅按上表用途使用 |

### 2.4 反模式（违反则指标不可复现）

1. **禁止使用 ADC2**：ADC2 与 WiFi 共用仲裁器，开 RF 时读数失效。只能用 ADC1。
2. **检测期间关闭 WiFi/BT**：RF 突发电流在 3.3 V 轨上产生 > 50 mV 波动，直接进入 1.59 Hz 带内。
3. **ADC 源阻抗 < 10 kΩ**：ESP32 ADC 采样保持电容充电不足会引入非线性。前置放大输出串 1 kΩ + 100 nF 到地。
4. **硬件高通截止 ≥ 0.1 Hz**：抑制传感器直流偏置与 ADC 1/f 漂移；截止频率必须远低于 `f0 = 1.5915 Hz`。
5. **模拟地与数字地单点连接**，模拟部分加屏蔽罩。

## 3. 配置参数

### 3.1 算法常量（机器可解析）

```yaml
# ---- 信号与时间基 ----
omega:      10.0          # [S2] rad/s, 待测信号角频率
f0:          1.5915494    # [S2] Hz, = omega / 2π
fs:        500.0          # [SPEC] Hz, 采样率（实际值须标定, 见 §9.3 A1）
dt:          0.002        # [SPEC] s, = 1 / fs
h1:          0.02         # [S2] 数值步长 = R * dt, R = omega
R:          10.0          # [S2] 尺度系数, 检测时固定 = omega

# ---- 振子参数 ----
lam0:        0.72         # [S2] 工作点（混沌态）
lam_c:       0.7335       # [S2] 参考等效阈值（浮点, 0.001 步长精扫）
damping:     0.5          # [S2] 线性阻尼系数
n_beta:      3            # [LK] 相位阵列路数
betas_deg:  [0.0, -120.0, 120.0]   # [APP] 各路初相偏置（度）——顺序即数组下标，禁止重排
phi0:        0.0          # [SPEC] 第 0 路初相, 运行时置 0 便于复现

# ---- 帧结构 ----
n_cycles:  150.0          # [S2] 每帧载波周期数
n_cycles_min: 48.0        # [LK] 硬下限, 低于此判据抖动
burn_frac:   0.5          # [S2] 前 50% Poincaré 点丢弃
step_per_cycle: 314.1592653589793   # = 2π / h1, 禁止取整为 314
frame_n:   47124          # [SPEC] = round(n_cycles * step_per_cycle)；上位机默认 94.2 s 只给 47100 点
frame_dur:   94.248       # [SPEC] s, = frame_n * dt
poc_total:  150           # [SPEC] 每帧总 Poincaré 点数 = n_cycles
poc_pts:     75           # [SPEC] 实际累加点数 = poc_total * (1 - burn_frac)
poc_skip:    75           # [SPEC] 前 75 点丢弃 = poc_total - poc_pts

# ---- 判决 ----
q_th:        0.08         # 当前生效门限；CALIB 成功后写 NVS 覆盖
q_th_default: 0.08        # [APP][S2] 出厂默认（上位机双端与阶段 2/3 同一口径），标定失败回退
q_th_pfa5:   0.347        # [LK] 等虚警门限 = 200 帧 H0 的 5% 分位；用它报 Pfa，不用它做默认
q_th_min:    1.0e-7       # [SPEC] pstd 塌缩下限（定点退化到同一格点），不是"断线检测"
q_peak_min:  5e-3         # [SPEC] 一帧 peak 低于此值判输入静默（≈ 20 LSB），见 §10.1
silent_n:    5            # [SPEC] 连续多少帧静默才报 ERR_INPUT_SILENT

# ---- 定点算术 ----
q_pre:       6            # [SPEC] 整数位（含符号）
q_frac:     12            # [S5] 小数位, F=12 与浮点同阈值
q_coef_frac: 30           # [SPEC] 系数/三角函数小数位（h1、cos）
q_one:      4096          # = 1 << q_frac
q_lsb:       0.00024414   # = 2^-12
q_max:    131071          # = 32.0 * 4096 - 1, 超出即溢出
ph_inc:  13671306         # [SPEC] 相位累加增量 = round(h1 / 2π * 2^32)

# ---- 任务与缓冲 ----
adc_chunk:  512           # [SPEC] 单次 DMA 读取样本数
ring_items: 8192          # [SPEC] 环形缓冲项数（uint16 计数）
task_core_acq:  0         # [SPEC] 采集任务绑定核
task_core_proc: 1         # [SPEC] 计算任务绑定核
prio_acq:     8           # [SPEC] FreeRTOS 优先级
prio_proc:    6           # [SPEC]
stack_proc: 8192          # [SPEC] byte
timeout_ms: 3000          # [SPEC] 帧超时, 超时丢弃

# ---- 联调下行（§8.4，v1 可选） ----
link_chunk: 1024          # [APP] 每包样本数，与上位机 CHUNK 一致
link_hdr:     21          # [APP] 数据包头长 = 4s + c + I + I + I + f
uart_baud: 460800         # [SPEC] 回放波特率；115200 只够 ×1 实时
replay_mult_max: 10       # [SPEC] 回放倍率上限（×10 → 19.5 KB/s，见 §8.4 带宽表）
```

### 3.2 参数依赖：改一项会连锁触发什么

| 改动 | 必须同步 | 必须重做的事 |
|---|---|---|
| `fs` | `dt`、`h1 = R*dt`、`frame_n`、`ph_inc` | **重扫 `lam_c`** `[S5]`——`h1` 变了，阈值跟着漂 |
| `omega` | `f0`、`R`、`h1`、`ph_inc` | 同上，且重标前置滤波器 |
| `R` | `h1`、`ph_inc` | **运行时参数**（"已知 R"由用户给出，非编译期写死），供 §9.3 A4 的失谐测试；单独改 R 不重扫 `lam_c` |
| `lam0` | — | 重跑 H0 标定 `q_th`；`lam0 ≥ 0.74` 会使 H0 自相变 `[S5]` |
| `q_th` | — | 改门限即改 Pfa。必须重跑 A5，并**同时报门限值与噪声条件**，否则数字无意义（§9.3） |
| `q_frac` | `q_one`、`q_lsb`、`q_max` | 重跑 §9.2 全部用例；`F ≤ 8` 时判据失效 `[S5]` |
| `n_cycles` | `frame_n`、`poc_pts` | 不得 < 48；缩短会同时抬高 `pstd` 与判决抖动 `[LK]` |
| `betas_deg` | — | 重算 §11.1 覆盖率表；**数组顺序即下标**，重排会让 `p_q16[]` 与日志错位 |
| `uart_baud` | `replay_mult_max` | 倍率上限 `= baud / (20·fs)`（8N1 每字节 10 bit、**int16 每样本 2 B**，协议 v2）；460800 时为 46，工程取 10 留余量 |

**`lam_c` 的重扫方法**：喂全零序列（仅内驱），在 `[0.70, 0.84]` 内以 0.001 步长扫 `lam`，取首个 `pstd < 0.1` 的点。必须 `n_cycles ≥ 190`（对应 T=1200 s），短窗会把「未收敛」读成「阈值更高」`[S5]`。

### 3.3 上位机默认值 ↔ 固件默认值（`[APP]`）

实现时按此表对齐，不要凭 §3.1 的 yaml 反推上位机行为——`[APP]` 的默认值写在控件初始化里，与 yaml 有 24 个样本的差异。

| 参数 | 上位机默认 | 固件默认 | 说明 |
|---|---|---|---|
| `omega` / `R` | 10.0 / 10.0 | 10.0 | 发送端 `omega` 与接收端 `R` 必须相等；`known` 模式**不做校验**，靠人保证 |
| `fs` | 500 | 500 | 接收端勾「跟随发送端的 fs」时用头包 `fs`；固件用 A1 标定值 |
| `duration` | 94.2 s → **47100 点 / 149.92 周期** | 94.248 s → **47124 点 / 150 周期** | 差 24 点，判据无差别；回放以头包 `n` 为准，`steps = n` |
| `sigma` | 0.05 | 不适用 | 固件面对真实噪声，靠 `CALIB` 现场标定与前置增益（§2.1） |
| `SNR` | −11.0 dB（滑块 −30…+5） | 不适用 | 仅用于生成向量；A4/A6 用 −7.4 dB。**力口径**（按 `lam` 归一，与 `sigma` 一起决定 `A`） |
| `SNR_E` | −15.0 dB（框架演示默认） | 不适用 | 仅「框架演示 Pfa/Pd」窗口用：`sigma = sqrt((A²/2)/10^(SNR_E/10))`，只填 `A` 与 `SNR_E`，`sigma` 只读反算。与上一行差 `10lg h1` = **−17 dB**，见 §3.4 |
| `alpha`（噪声谱） | 0（白噪）/ 1（1/f 色噪） | 不适用 | 见 §3.4 |
| `lam0` | 0.72 | 0.72 | 必须 `< lam_c = 0.7335` |
| `q_th` | 0.08 | 0.08（标定后覆盖） | 见 §3.1 三条门限的分工 |
| `betas` | `0, -120, +120` | 同 | 顺序即下标，禁止重排 |
| `burn_frac` | 0.5 | 0.5 | 前 75 个 Poincaré 点丢弃 |
| 阵列 | 三相位（可切单路 β=0） | 三相位 | 单路只用于带宽测量与估幅 |
| `do_est` | 开（仅 `detected` 时执行） | 无 | v2，§11.4 |
| R 模式 | `known`（默认）/ `hint` / `auto` | `known` | `hint` 的使用边界见 §8.4 |

### 3.4 噪声类型（`[APP]` 已实现，固件无需实现）

上位机可注入两种噪声，用 `make_noise(alpha)` 生成：

| `alpha` | 类型 | 实现 | 谱形 |
|---|---|---|---|
| 0 | 白噪 | `rng.standard_normal` | 平坦 |
| 1 | 1/f 色噪 | `rfft` 后按 `f^(-alpha/2)` 加权、去 DC、再归一化到单位方差 | 低频抬高 |

**关键**：色噪只改谱形，**不改 σ 口径**——归一化后每样本标准差仍是 `sigma·sqrt(h1)`。所以 §3.1 的 `A`、`lam_eff`、`q_th` 全部沿用。固件侧不需要生成噪声，但 `CALIB` 必须在**两种谱形**下都验一遍：真实磁通门的 1/f 拐点若落在 1.6 Hz 附近，白噪下标定的 `q_th` 会偏乐观（`[TODO]`）。

**两套 SNR 口径，别混着引用**：力口径按 `lam0` 归一（`SNR = 20lg(A/lam0)`，配 `sigma` 定 `A`），每样本口径 `SNR_E = 20lg(A/(σ√2))`。两者差 `10lg h1`，本链路 `h1 = 0.02` → **−17 dB**。所以界面读到 −7.4 dB 的那一帧，每样本是 **+9.6 dB**，波形图上本该看得见正弦；反之 −15 dB（`SNR_E`）的框架演示里看不到波形也是正常的。**不要用「波形看不出来」判信号没发出去**，判据只有 `pstd` 与相干投影。

## 4. 定点算术契约

### 4.1 双格式：状态 Q6.12 + 系数 Q0.30

**状态量**（`x`, `y`, 样本 `u`）与**系数**（`h1`、`h1/2`、`h1/6`、`lam0`、`cos`）必须用两种格式，否则 RK4 无法成立。

| 类别 | 格式 | 容器 | 范围 | 分辨率 |
|---|---|---|---|---|
| 状态 `x`, `y`, `u` | Q6.12 | `int32_t` | `[-32.0, +31.9998]` | `2.4414e-4` |
| 系数 `h1`, `h1/2`, `h1/6`, `cos` | Q0.30 | `int32_t` | `[-2.0, +2.0)` | `9.3132e-10` |
| `lam0` | **Q6.12** | `int32_t` | 同状态 | `2.4414e-4` |

`lam0 = 0.72` 若用 Q0.30 是 `7.73e8`，**溢出 int32**（Q0.30 的值域只有 `[-2, 2)`）。故 `lam0` 必须留在 Q6.12（`2949`，实际 `0.719971`，偏差 `1.2e-4`，占阈值余量 `0.0065` 的 1.8%，不影响判决），与 `cos` 相乘时走 `qmul_coef` 的混合路径（§4.2）。重扫 `lam_c` 时必须用同一个量化后的 `lam0`。

**为什么必须分开**：`h1/6 = 0.0033333` 若存成 Q6.12 只有 `14` 个 LSB（`14/4096 = 0.003418`，相对误差 **2.5%**），每步末态组合都会系统性偏大，等效于把步长改掉 2.5%——远超 ±0.1% 的频率带宽，判据直接失效。存成 Q0.30 是 `3579139`，相对误差 `3e-10`。

| 常量 | Q0.30 值 | 实际值 | 相对误差 |
|---|---|---|---|
| `h1 = 0.02` | `21474836` | `0.0199999996` | `2e-8` |
| `h1/2` | `10737418` | `0.0099999995` | `5e-8` |
| `h1/6` | `3579139` | `0.0033333297` | `8e-6` |

**与阶段 5 的关系**：`[S5]` 用 Q2.12（W=14 窄字长，模拟 FPGA），且 **`cos` 用双精度、`h1` 用浮点**——即 `[S5]` 从未验证「系数也定点化」。本规格的 Q6.12 状态与 `[S5]` 的小数位相同（舍入噪声同量级），但额外引入了 Q0.30 系数与 LUT `cos`，**这是 `[S5]` 未覆盖的新误差源**，必须由 §9.2 T2/T9 与 §11.3 的 `cos_lut` 项验证。

### 4.2 乘法与舍入

```c
// 状态 × 状态 -> 状态 (Q6.12 × Q6.12 -> Q6.12)
static inline int32_t qmul(int32_t a, int32_t b) {
    return (int32_t)(((int64_t)a * b + (1 << 11)) >> 12);
}

// 状态 × 系数 -> 状态 (Q6.12 × Q0.30 -> Q6.12)
static inline int32_t qmul_coef(int32_t a_q12, int32_t c_q30) {
    return (int32_t)(((int64_t)a_q12 * c_q30 + (1LL << 29)) >> 30);
}
```

- 两个插件的中间积都必须 `int64_t`：`qmul` 的上界 `131071² = 1.7e10`，`qmul_coef` 的上界 `131071 × 2^31 = 2.8e14`，均超 `int32`。
- `qmul_coef` 的值域要求 `|a_q12| ≤ 2^17`（即状态 ≤ 32.0），与 Q6.12 范围一致。
- 舍入为「加半后算术右移」，允许 ±1 LSB 偏差；不要求 round-half-away-from-zero。
- `qadd` / `qsub` 为饱和加，见 §4.3。**但 §4.4 的末态组合不得用 `qadd`**，见该节说明。

### 4.3 溢出策略

| 情形 | 动作 |
|---|---|
| `qadd`/`qsub` 结果超 `[-131072, 131071]` | 钳位到边界，`ovf_cnt++` |
| 单帧 `ovf_cnt > 0` | 该帧 `pstd` 置 `NAN`，判决输出 `ERR_OVF`，不上报 0/1 |
| 单帧 `ovf_cnt > 100` | 判定参数失配（`lam0` 或输入幅度错误），停机 LED 快闪 |

### 4.4 单步积分（固定字段，实现必须逐项对应）

方程为一阶化系统 `x' = y`、`y' = -0.5y + x³ - x⁵ + lam0·cos(τ) + u`。

```
输入:  状态 x, y (Q6.12)   相位 ph (uint32)   样本 u_cur, u_nxt (Q6.12)
常量:  H1_Q30 = 21474836   HH_Q30 = 10737418   H6_Q30 = 3579139      (Q0.30)
       LAM_Q12 = 2949     HALF_Q12 = 2048                            (Q6.12)

u_mid = (u_cur + u_nxt) >> 1                                  // 算术右移 1 位, 精确
drv(ph, u) = qadd(qmul_coef(LAM_Q12, cos_q30(ph)), u)

f(xx, yy, d):
    x2 = qmul(xx, xx)
    x3 = qmul(x2, xx)
    x5 = qmul(x2, x3)                       // 三次乘, 禁止 pow()
    return qsub(qsub(qadd(x3, d), x5), qmul(HALF_Q12, yy))

k1x = y                        k1y = f(x,            y,            drv(ph,             u_cur))
k2x = y  + HH·k1y              k2y = f(x + HH·k1x,   y + HH·k1y,   drv(ph + PH_INC/2,  u_mid))
k3x = y  + HH·k2y              k3y = f(x + HH·k2x,   y + HH·k2y,   drv(ph + PH_INC/2,  u_mid))
k4x = y  + H1·k3y              k4y = f(x + H1·k3x,   y + H1·k3y,   drv(ph + PH_INC,    u_nxt))

// 末态组合: 以下三行必须逐字照做, 不得改写为 qadd 连加
int64_t sx = (int64_t)k1x + 2LL*k2x + 2LL*k3x + k4x;
int64_t sy = (int64_t)k1y + 2LL*k2y + 2LL*k3y + k4y;
x = qadd(x, (int32_t)((sx * H6_Q30 + (1LL << 29)) >> 30));
y = qadd(y, (int32_t)((sy * H6_Q30 + (1LL << 29)) >> 30));

ph += PH_INC                                                  // uint32 自然溢出 = 跨 2π
```

其中 `HH·k` 表示 `qmul_coef(k, HH_Q30)`，`H1·k` 表示 `qmul_coef(k, H1_Q30)`。

**为什么末态不能复用 `qmul_coef`**：`sx` 的量级上界为 `6 × q_max = 786426`，超出 `qmul_coef` 的入参值域（`≤ 2^17`），必须先 `int64` 累加再内联移位。用 `qadd` 连加则会中途饱和——这正是「每步都少一点、最后判据崩掉」的典型来源。

**三条硬性禁止**（违反即 `[S5]` 记录的 0.77 假阈值重演）：

1. `k2`/`k3` **必须**用 `h1/2`。旧实现误用整步 `h1`，积分精度退化到 RK2，相变点被推到 0.77 `[S5]`。
2. `x^5` 用 `x2=x*x; x3=x2*x; x5=x2*x3`，三次乘。禁止 `pow()`，禁止 `x*x*x*x*x` 串联（尾两个乘法会越界）。
3. `u` 只作为 `drv` 的独立加项，**不得**并入 `lam0`（`lam0 + u` 是错误写法，会改变 `lam_eff` 的物理含义）`[S5]`。

**`cos_q30` 规格**（这是 `[S5]` 未覆盖的新误差源）：

| 项 | 值 |
|---|---|
| 表长 | 1024 项，覆盖 `[0, π/2)`，Q0.30 |
| 索引 | `idx = ph >> 22`；`frac = (ph >> 6) & 0xFFFF` |
| 插值 | `lut[idx] + ((lut[idx+1] - lut[idx]) * frac >> 16)` |
| 象限折叠 | 用 `ph` 的最高两位选择符号与镜像 |
| 最大绝对误差 | `5e-6`（线性插值 `Δ²/8`，`Δ = 2π/1024`） |
| 折算到激励 | `5e-6 × 0.72 = 3.6e-6`，约为 Q6.12 一个 LSB 的 1.5%，可忽略 |

表占 `1024 × 4 B = 4 KB`，放 `const` 段（flash），不占 DRAM。若 §9.2 T9 不通过，先试 4096 项表，再试 CORDIC，**不得**改用 `cosf()`（无硬件双精度，且破坏跨平台一致性）。

### 4.5 相位累加器与 Poincaré 采样

用 DDS 式满量程相位：`uint32_t ph`，`2^32 ≡ 2π`，每步 `ph += PH_INC`，溢出即跨过一个载波周期。

```c
uint32_t prev = ph;
ph += PH_INC;
if (ph < prev) {                    // 本轮跨过 2πk
    uint32_t frac = ph;             // 跨线**后**的余量, 0..PH_INC-1
    // 权重 = 跨线**前**走过的步内比例 = 1 - frac/PH_INC, 必须取补角
    uint32_t before = PH_INC - frac;
    int32_t alpha_q30 = (int32_t)((uint64_t)before * 1073741824ull / (uint64_t)PH_INC);
    poc_val = qadd(x_prev, qmul_coef(qsub(x, x_prev), alpha_q30));
    poc_push(poc_val);
}
x_prev = x;                          // 每步更新, 供下一次跨周期插值
```

`alpha_q30` 的分子 `before × 2^30` 最大 `1.37e7 × 1.07e9 = 1.47e16`，**必须用 `uint64` 中间量**（`uint32` 会截断）。结果落在 `[0, 2^30]`，正是 `qmul_coef` 要求的 Q0.30 值域：`before = PH_INC`（恰在步末跨线）时 `alpha_q30 = 2^30`，乘积精确复现 `x`。若 `qmul_coef` 的入参上界写死为 `2^30-1`，需在此钳一位，误差 < 1 LSB。

**补角必须取，这不是可选的写法差异。** `frac` 是**跨线后**的余量，截点位于 `tau + (1 - frac/PH_INC)·h1`；直接把 `frac/PH_INC` 当权重，截点会落到 `tau + (frac/PH_INC)·h1`，即从跨线处反向偏出 `|1 - 2·frac/PH_INC|·h1`，最大一个整步，且偏差随 `frac` 在 `[0, h1]` 内摆动。同一段浮点 RK4 只换权重实测 `[APP]`：

| 状态 | `frac` 口径（kernel 正确） | 余量口径（本节的常见错法） | 按步数取整 |
|---|---|---|---|
| 混沌 `lam=0.72` | `4.303e-1` | `4.308e-1` | `4.612e-1` |
| 临界 `lam=0.7335` | `3.771e-1` | `3.768e-1` | `4.017e-1` |
| 周期 `lam=0.74` | **`3.2e-6`** | **`1.2e-2`** | `3.4e-2` |

混沌态两种写法看不出差别（差 0.1%），**周期态差 3.6 个量级**——所以这个错在 T5/T7 上不会暴露，只在 T4/T8 上翻车，而且症状与「按步数取整」几乎一样（都是 `1e-2` 量级），极易误诊为「插值没做对」而反复改 `idx`。定位时直接对照本表。

**与 `tools/kernel_src.py` 的对应**：内核写 `frac = (2π·idx − τ)/h1` 并 clip 到 `[0,1]`，即「跨线前比例」，与本节 `before/PH_INC` 逐位等价（`idx` 就是本节的溢出计数）。改内核口径必须同步改本节，否则 T8 与 `[S5]` 对不上。

**禁止**按步数取整判周期（如 `if (n % 314 == 0)`）。按步数取整会把周期态 `pstd` 从 `3.2e-6` 抬到 `3.4e-2`，压掉 4 个量级动态范围 `[S2]`。

`PH_INC = 13671306` 的取整误差为 `+0.5 LSB`（精确值 `13671305.512`）/步，折算 `7.1e-10 rad`，150 周期累积 `5.4e-6` 周期，可忽略。

### 4.6 `pstd` 计算

```c
// poc 点以 Q6.12 存, N = 实际 poc_cnt（正常帧 = poc_pts = 75，只取后 50%）
int64_t s1 = Σx;                    // Q6.12, |x|≤2, N=75 -> ≤ 6.2e5
int64_t s2 = Σ(x*x);                // Q8.24, |x|≤2, N=75 -> ≤ 5.1e9 (int64 安全, 不必移位)
float mean    = (float)s1 / (float)N / 4096.0f;        // 2^12
float mean_sq = (float)s2 / (float)N / 16777216.0f;    // 2^24
float var = fmaxf(mean_sq - mean * mean, 0.0f);
pstd = sqrtf(var);
```

- 统计后处理用 `float`：仅每帧 1 次，不影响逐样本确定性。
- `s2` 无需右移预处理：`N=75`、`|x|≤2` 时上界 5.1e9，远低于 `int64` 上限。若 `N > 2e6` 才需要分段累加。
- 只有 `s1`/`s2` 两个累加器，无点集存储——这是流式架构成立的前提。
- `pstd` 的确定性由 §4.4 的定点积分保证，不由统计后处理保证。
- 分母必须用**实际** `poc_cnt`，不得写死 `POC_PTS`：帧被截断、`ERR_OVF` 提前收尾、回放 `n < FRAME_N` 时点数会少，用常量做分母会系统性压低 `pstd`（分母偏大 → 方差偏小），表现为「短帧更容易判成有目标」。
- **定点地板**：12 位小数位下周期态 `pstd` 的地板是 `2.7e-3`（F=12）/ `7.6e-3`（F=10），来自每步对驱动项与状态的舍入；浮点同一条件是 `3.2e-6`。门限 `0.08` 离地板仍有 30 倍余量，判决不受影响，但**浮点值不能当固件指标**（§9.2 T8）。

**`pstd` 不能用来判断线/静默。** `u ≡ 0` 时系统只剩内驱，而 `lam0 = 0.72 < lam_c` → 仍处于混沌态，`pstd` 是 **0.43 量级**（三路实测 `[0.431, 0.527, 0.572]`，`[APP]`），不是 0。也就是说：传感器断线、ADC 断流、前置放大掉电，在 `pstd` 上看起来与「纯背景噪声」几乎一样（噪声帧 0.36–0.48），**只会安静地判「无」**，不会报错。真正的 `pstd` 塌缩是另一种情形：`lam0` 越过 `lam_c`（`lam0=0.74` 时三路 `3.0e-6 / 2.4e-5 / 4.0e-6`）或定点字长不足导致轨迹锁死在少数格点（`F=4` 时全程 `pstd ≈ 0`）。两种情况必须用不同判据区分：

| 现象 | 物理含义 | 判据 | 处理 |
|---|---|---|---|
| `pstd ≈ 0.43`、`peak ≈ 0` | 输入静默（断线/断流） | 输入电平，见 §10.1 `ERR_INPUT_SILENT` | 不输出 0/1 |
| `pstd < q_th_min` | 定点塌缩或 `lam0` 越界 | `q_th_min = 1e-7` | `ERR_OVF` / `ERR_PARAM` |
| `pstd < q_th` 且 `peak` 正常 | 共振 → 检测到目标 | `pstd` 比较 | 输出 1 |

## 5. 数据流与任务模型

### 5.1 流式架构（不缓存整帧）

一帧 `47124` 样本以 `int16` 缓存要 `92 KB`，仍超出本工程给检测链留的 `64 KB` 峰值预算。因此**必须流式**：

```
ADC DMA ──► on_sample(u) ──► duffing_step(3 路) ──► poc_push ──► 滑动 pstd 累加
                                                                    │
                                          帧末 ──► pstd ×3 ──► min() ──► 判决
```

内存占用与帧长无关：`3 × (状态 8 B + 累加器 16 B) + 环形缓冲`。`[SPEC]` 峰值 ≤ 64 KB。

**上位机的「驱动表预算」不可照搬**（2026-11-26 提速改造，见 `00-总览/性能优化与基准.md`）：PC 侧把 `lam·cos(τ+β)+s` 在循环外整列预算成 3 条 Python float 列表（单列 `3 × 47124` 个 float，含对象开销约 **4.5 MB**），换来 11 倍速；固件上这条路**既无必要也不可行**——`cos_q30` 是 1024 项 LUT（4 KB，flash），驱动项每步实时算两个 `qmul` 即可。固件若照抄「整帧预存驱动项」，`47124 × 3 路 × 4 B ≈ 566 KB`，直接顶穿 64 KB 预算，A7 必挂。

### 5.2 双核分工

| 核 | 任务 | 优先级 | 职责 |
|---|---|---|---|
| 0 | `acq_task` | 8 | `adc_continuous_read` → 写 ringbuf，只做搬运，不做算术 |
| 1 | `proc_task` | 6 | 从 ringbuf 取样本 → `duffing_step` ×3 → 帧末判决 |

丢样判定：`acq_task` 写入时若 ringbuf 满，`drop_cnt++`；一帧内 `drop_cnt > 0` 则该帧作废（时间轴不连续，Poincaré 点失效）。

**与上位机的对应关系**（`[APP]`）：`_recv` 线程只做「收包 → 按 `seq` 写入定长数组 → 凑齐提交」，与 `acq_task` 同职责，**不含任何算术**；`_worker` 线程从队列取整帧、算三路 `pstd`、出判决，与 `proc_task` 同职责；`_drain` 每 100 ms 取结果刷界面，与 `uplink` 同职责。上位机用两个线程而不是一个，是因为 `recvfrom` 会阻塞而判决要跑 0.15 s（优化前 1.5 s，见 `00-总览/性能优化与基准.md`）；固件里对应的是两个任务 + ringbuf，理由相同：**采集绝不能被判决阻塞**。若把判决写进采集回调，94 s 的帧会丢样，`drop_cnt` 一路涨，帧帧作废。

### 5.3 状态机

```
BOOT ──► CALIB ──► RUN ──► (ERR) ──► RUN
           │                    └──► HALT
           └── 详见 transitions
```

| 状态 | 进入条件 | 动作 | 退出 |
|---|---|---|---|
| `BOOT` | 上电 | 读 NVS 配置、自检内存、`ovf_cnt=0` | 自检通过 → `CALIB` |
| `CALIB` | 自检通过 | 采集 `CAL_FRAMES=20` 帧纯噪声，标定 `q_th`（5% 分位）；失败则回退 `q_th_default` | 完成 → `RUN` |
| `RUN` | 标定完成 | 逐帧判决，`TRIG` 输出；`peak < q_peak_min` 连续 `SILENT_N` 帧 → 报 `ERR_INPUT_SILENT` 但不切状态 | 连续 3 帧 `ERR_OVF` → `ERR` |
| `ERR` | 溢出/失配 | LED 快闪 2 Hz，`TRIG` 保持低，日志上报 | 收到 `RESET` 命令或 60 s 超时 → `RUN` |
| `HALT` | 参数致命错误 | 停止采集，等待复位 | 仅硬件复位 |

### 5.4 帧边界与判决

```
帧开始: 清 s1, s2, poc_cnt, ovf_cnt
每样本: duffing_step ×3 → 每路独立 poc 累加
        poc_cnt += 1
        if (poc_cnt > POC_SKIP)  { s1 += x; s2 += x*x; }    // POC_SKIP = 75
poc_cnt == POC_TOTAL 时: 计算 3 个 pstd（各用 75 个点）
帧结束: p = min(pstd[0], pstd[1], pstd[2])
       detected = (p < q_th)
```

`POC_SKIP = 75` 即 `burn_frac = 0.5`：前 75 个 Poincaré 点丢弃，只用后 75 个。**不要**改成「帧末统一丢弃」——那需要缓存全部 150 个点，破坏流式架构。

三路取 `min` 是**判决**用法；测量带宽或估幅时必须单路（`beta=0`），因为三路取 `min` 会把别的振子在锁频态的伪相变捞进来 `[S2]`。

**四条帧边界约束**（固件与 `[APP]` 必须一致，否则「两边都算对了但结论不同」）：

1. **参数只在帧边界生效**。上位机的做法是主线程每 100 ms 把输入框刷进 `self.cur` 快照，工作线程**每帧开头**读一次。改到一半的 `R`/`lam0` 会让同一帧前后步长不一致，`h1` 不再恒定，Poincaré 截面失去意义。固件同理：NVS 写入只置「待生效」标志，`proc_task` 在帧末才切换。
2. **新帧开始即丢弃残帧**。上位机收到头包直接 `self.buf = FrameBuf(obj)` 覆盖旧的，不排队、不拼接。固件收到 `H` 亦须立即复位装配缓冲并 `drop_cnt++`。
3. **数据包必须校验 `frame`**。上位机对 `frame` 与当前头包不符的包直接丢弃（丢了头包的残包）。只按 `seq` 写而不校验 `frame`，会把上一帧的尾包写进新帧，制造「看似完整、实则错位」的帧。
4. **积分步数由样本数决定**。`steps = n`（因为 `h1 = R·dt` 固定时 `n_cycles = n·h1/2π` 反推回来恰好是 `n`）。本地采集时 `n = FRAME_N`；回放时以头包 `n` 为准，**不得写死 47124**——上位机默认 94.2 s 只给 47100 点，写死会多积 24 步（尾部样本早耗尽，驱动归零），`pstd` 偏低。回放还须满足 §9.1 的 `n ≥ 15080`。

### 7.3 与上位机的依赖关系

`scripts/export_vectors.py` 需要读取本仓库 `tools/kernel_src.py` 的 `simulate_fixed_seq` 作为参考实现。**固件不得复制该 Python 代码**，只能通过导出的 `.bin` 向量对比。

**内核形态（2026-11-26 重构后）**：`simulate_seq` 内部按振子数分两条路径——`m ≤ 32` 走微内核（每通道纯标量 RK4），`m > 32` 走向量路径（沿通道维一次算 `m` 路）。两条路径对同一问题给出**逐位相同**的 `pstd`（测试钉在 `m = 32/33` 边界），签名与 `simulate_fixed_seq` 都**未变**。所以：导出向量不用关心它走哪条路径；固件实现对应的是 §4.4 的**单步字段**，与路径无关——两条路径执行的是同一套 `k1..k4` 与同一条末态组合式。

**数值一致性验收**（本仓库做法，固件侧可直接借用）：浮点侧不比 `allclose`，而是对 `pstd`/`mx`/Poincaré 点矩阵取 `sha256` 逐位比对（`tests/golden/kernel_ref.json`），因为混沌态下 1 ulp 的差会被指数放大成可见差异——容差在这里既太松又太严。固件侧同理：定点是全整数确定性运算，同输入必须**逐位复现**，见 §9.1 L2。

浮点 `simulate_seq` 也可以读，但**只用于「趋势是否一致」的旁证**：指标与容差一律以 `simulate_fixed_seq`（同一 `F`）为准。原因是 12 位小数位下周期态 `pstd` 地板是 `2.7e-3`，浮点是 `3.2e-6`，拿浮点当基线会得到「正确实现也不达标」的结论（§9.2 T8/T9）。

### 8.3 串口上报格式（`uplink`）

文本日志（人类可读，1 行/帧）：

```
F<frame_id> p=<p0>,<p1>,<p2> min=<pmin> th=<q_th> d=<0|1> ovf=<n> drop=<n> t=<ms>
```

二进制上报（`TRIG` 触发后，`0xA5` 帧头，小端）：

```c
typedef struct __attribute__((packed)) {
    uint8_t  magic;      // 0xA5
    uint32_t frame_id;
    int32_t  p_q16[N_BETA];   // pstd × 65536
    uint32_t ovf_cnt;
    uint16_t crc16;      // CCITT, 覆盖前 21 字节
} report_t;
```

上报字段与上位机状态条一一对应：`p_q16[]` ↔ 阵列柱状图、`d` ↔ 判决、`ovf`/`drop` ↔ 日志告警。`best_ch`（`pstd` 最小的振子下标，`int8_t`，可加在 `ovf_cnt` 之后）只是诊断量，判决仍取 `min`，不得据 `best_ch` 反推目标相位——初相盲区下「最小那一路」与真实相位无关。

### 8.4 下行联调格式（`link_ingest`，v1 可选）

与 `[APP]` 的 UDP 协议**同构**，只把传输层从 UDP 换成 UART（检测期间禁 RF，§2.4）。三类包统一 4 字节魔数 `WBDX` + 1 字节类型：

| 包 | 类型 | 载荷 | 长度 |
|---|---|---|---|
| 头 | `H` | UTF-8 JSON：`v, frame, n, fs, w_hint, amp, sigma, alpha, snr_db, has_sig, has_noise, duration, phase, ts, scale, t0, sig_t0, sig_dur, sig_epoch, cov` | ≤ 512 B |
| 数据 | `D` | `struct "<4scIIIf>"`（魔数 / `'D'` / `frame` / `seq` / `nseq` / `fs`）+ **`int16` 小端样本** | **21 + 2·1024 = 2069 B** |
| 尾 | `T` | UTF-8 JSON：`{frame, sent, nseq}` | ≤ 64 B |

**协议 `v = 2` 起样本是 `int16`**（`v = 1` 是 `float32`，已废弃）：满量程对应 ±1.0，`scale = 32768` 随头包下发，1 LSB `= 3.05e-5`。选它是因为 ESP32 的 ADC 本来就是整数计数——**收发两端从此都在整数域里说话**，省掉一次浮点解析，包长也从 4117 B 减到 2069 B。

一帧 = 1 个 `H` + `ceil(n/1024)` 个 `D` + 1 个 `T`。`n = 47124` 时是 **47 个数据包、约 95 KB**（`n = 47100` 时 46 个包）。

**连续发送与目标窗（v2 新增）**：上位机启动后**一直发、不自动停**，帧号从 0 单调递增、没有"总帧数"；目标可以在发送过程中随时附加，所以头包里必须带四个时间字段——`t0`（本帧首样本的会话绝对时间）、`sig_t0`/`sig_dur`（目标窗起止）、`cov`（本帧覆盖率）。固件侧**必须用同一套 `window_coverage()` 口径自己重算 `cov`**，不能直接信 `cov`：这是唯一能发现"发送端以为在发目标、固件却当背景帧"的办法。窗口不对齐帧，所以每隔一段时间必然出现 `0 < cov < 1` 的帧——这类帧**既不算 Pd 也不算 Pfa**，只计数。

**装配规则**（与 `FrameBuf` 逐条对齐，缺一条就会出现「两边都算但结果不同」）：

1. **头包开新帧**：收到 `H` 立即丢弃未装配完的旧帧，不排队、不拼接（§5.4 约束 2）。
2. **按 `seq` 定位**：写入 `buf[seq·1024 : …]`；重复 `seq` 直接丢弃（UDP 回环会重复，UART 重传也会）；`frame` 与当前头包不符的包丢弃。
3. **尾包提交**：收到 `T` 即提交，**不等 `n` 点齐**——尾包先到说明发送端已发完，缺的就是丢了。
4. **缺包补零并标记**：`got < n` 时缺口保持 0，`miss` 计入日志。上位机补零后照算，**固件必须额外标记该帧不可信**（`ERR_FRAME_GAP`，§10.1）：补零会压低 `pstd`，把「丢包」伪装成「检测到」，方向恰好是危险的那一侧。
5. **超时丢弃**：3 s 内未凑齐 → 丢帧，`drop_cnt++`。

**样本换算**：线上是 `int16`（LSB `= 1/32768 = 3.05e-5`），内部是 Q6.12（LSB `= 1/4096 = 2.44e-4`），换算就一条算术右移：

```c
int32_t q_q12 = ((int32_t)q_i16) >> 3;      /* 32768/4096 = 8，算术右移保符号 */
```

所以线上分辨率比内部格式细 8 倍，**线上量化不构成瓶颈**，瓶颈仍在 Q6.12。对 `A = 0.0199`（`int16` 652 LSB → Q6.12 82 LSB）、每样本噪声 29 LSB 的信号，量化损失 < 1%，可忽略——**但不要把这条链路当成「ADC 量化仿真」**：`make_frame(adc_bits=…)` 的满量程是按本帧峰值自适应的（`fsr = 4·max|rx|`），与固定量程 ADC 不是一回事，两者混用会得出「8 bit 也够」的错误结论（§11.2 的位数敏感性结论必须带这个前提引用）。

**带宽预算**（决定 `replay_mult_max`）：

| 回放倍率 | 数据率 | UART 最低波特率（8N1） | 可行性 |
|---|---|---|---|
| ×1（实时） | 1.0 KB/s | 10 kbaud | 任意波特率 |
| ×10 | 9.8 KB/s | 98 kbaud | `115200` 够用；`460800` 更宽裕 |
| ×250（上位机「尽快」） | 244 KB/s | 2.4 Mbaud | **不可行**，改用 SD 卡或本地 ADC |

上位机「尽快」模式每包只隔 2 ms，是给回环 UDP 用的；UART 没有这个带宽。**联调时把发送节奏设成「实时×10」**，两侧才跑得动。换成 `int16` 后 ×10 只要 98 kbaud（`float32` 时代是 195 kbaud），`115200` 就从"不够"变成了"够"。

**`w_hint` 的使用边界**：头包里的 `w_hint` 是发送端的 `omega`，属**联调旁路**。固件 v1 只接受 `known` 模式（`R` 由 NVS 或命令给）；`hint` 只允许联调脚本用来对表，**不得进入正式判决流程**——那等于把待测量当作已知量，检测本身就没有意义了。上位机界面上把 `hint` 标为「跟随发送端」并附说明，就是防止误用。

| L1 单元 | `test/host` | 否 | 全部用例通过 |
| L2 回放 | `test/host` 读 `vectors/` | 否 | `pstd` 与 `EXPECTED.json` **逐位相等**（定点为确定性整数运算，不设容差；理由见下） |
| L3 上板 | `test/board` | 是 | §9.3 全部指标达成 |

L1/L2 用主机编译器（`gcc -DQ_HOST_TEST`），`duffing.c` 不得包含任何 IDF 头文件。

**向量导出规则**（`scripts/export_vectors.py` 必须照做，否则 T5 会偶发失败却查不出原因）：

| 规则 | 原因 |
|---|---|
| 显式传 `phase=0`（或成组导出 12 个相位） | 上位机的 `make_frame` 默认**每帧随机初相**，`A = 0.02` 时单振子只有 26.6% 的相位能越线（§11.1）；随机相位导出的单条 `vec_h1.bin` 有 73% 概率判「无」 |
| `n ≥ 15080`（48 周期） | 低于此值判据抖动，`pstd` 跨门限 `[LK]` |
| 不用 `adc_bits` 模拟固件量化 | 该参数按本帧峰值自适应满量程，与固定量程 ADC、Q6.12 截断都不是一回事（§8.4） |
| 同时导出 `float32` 原序列与期望 `pstd` | 固件侧自己量化，才能在 T9 里分辨「量化误差」与「实现错」 |
| 记录 `n`、`fs`、`R`、`lam0`、`burn_frac`、`betas` | 缺任一项，`pstd` 无法复算——这些都在 `EXPECTED.json` 里，不在 `.bin` 里 |
| `.bin` 只装**接收序列**（信号 + 噪声），不含 `lam0·cos τ` | 策动力由 `drv()` 在积分内产生（§4.4）；混进样本等于把 `lam0` 算两遍，`lam_eff` 直接错 |

**L2 为什么改为逐位相等**：定点路径每一步都是 `int32` 整数加乘与移位，同一输入序列、同一 `F`、同一 `burn_frac` 下结果**完全确定**，不存在「同对数档」这种模糊判据。改前用容差会漏掉两类真错：① `u_mid` 用了 `(u_cur+u_nxt+1)>>1` 的舍入版本（每步差 1 LSB，`pstd` 差 1e-4 级，容差放过去了）；② Poincaré 插值权重取成余量口径（只有 F=12 的周期态能分辨，见 T8）。浮点侧同理改用哈希而非容差（`tests/golden/kernel_ref.json`）——**混沌系统里 1 ulp 会被指数放大，容差既太松又太严**。

### 9.2 单元用例（期望值固定）

| ID | 用例 | 输入 | 通过判据 |
|---|---|---|---|
| T1 | `qmul` / `qadd` 边界 | `qmul(4096,4096)`、`qmul(-4096,4096)`、`qadd(131000, 1000)` | `4096` / `-4096` / `131071`（饱和，`ovf_cnt++`） |
| T2 | Q6.12 ≈ 浮点 | 同一零序列，`lam` 扫 `[0.70,0.84]` | 首个 `pstd<0.1` 的 `lam` 与浮点基线差 ≤ 0.002（2 个精扫网格） |
| T3 | 无信号纯内驱 | `u ≡ 0`，`lam0=0.72`，150 周期 | `pstd ∈ [0.33, 0.48]`（混沌带）`[LK]` |
| T4 | 越过阈值 | `u ≡ 0`，`lam0=0.74` | `pstd < 0.01`（F=12 实测 `2.7e-3`，F=10 为 `7.6e-3`） |
| T5 | 有信号判「有」 | `vec_h1.bin`（`A=0.02, sigma=0.05, theta=0`） | `pstd < q_th` 且 `detected==1` |
| T6 | 错 R 判「无」 | 同 `vec_h1.bin`，`R=10.5` | `pstd > q_th` 且 `detected==0` |
| T7 | 纯噪声判「无」 | `vec_h0.bin` | `detected==0` |
| T8 | Poincaré 精确插值 | 周期态 150 周期，`lam=0.74` | **`pstd < 6e-3`**。F=12 正确实现 `2.7e-3`；插值权重取「跨线后余量」`1.2e-2`（4.4×，失败）；按步数取整 `3.4e-2`（失败）。**不得用浮点的 `1e-4` 当门槛**，见下方说明 |
| T9 | 与定点参考一致 | `vec_h1.bin` | `abs(log10(p_fw) - log10(p_ref)) ≤ 0.2`，`p_ref` 取自 `simulate_fixed_seq(F=12)`，**不是浮点内核** |
| T10 | 溢出钳位 |  注入 `x=31.9` | 状态钳到 `131071`，`ovf_cnt > 0`，该帧输出 `ERR_OVF` |
| T11 | 输入静默可分辨 | `u ≡ 0`，`lam0=0.72`，150 周期 | `pstd ∈ [0.40, 0.60]`、`detected==0`，**且 `err==ERR_INPUT_SILENT`**；只靠 `pstd` 判「无」即失败 |

**T8/T9 为什么不能用浮点当基线**：12 位小数位对驱动项与状态的逐步舍入本身就是一台噪声源，周期态 `pstd` 的地板因此被抬到 `2.7e-3`（F=12），而浮点内核在同一条件下是 `3.2e-6`——**差 3 个量级**。若照浮点写 `pstd < 1e-4`，正确实现也会失败；若照浮点写 T9 的 0.2 对数容差，误差会是 2.9，同样必然失败。固件的一切期望值都要从 `simulate_fixed_seq`（§7.3）取，浮点值只用于判断「趋势是否一致」，不能当指标。另注意 F=10 时正确与写反只差 1.9×（`7.6e-3` vs `1.4e-2`），**T8 只在 F=12 上有分辨力**，这也是 §3.1 把 `q_frac` 钉在 12 的理由之一。

T3/T4 的 `[0.33, 0.48]` 与 `<0.01` 来自 `[LK]`/`[S5]` 实测带，按**区间**判，不按点判。T3 的 `u ≡ 0` 是确定性输入（浮点 `pstd = 0.431`、三路 `0.431/0.527/0.572`，F=12 定点 `0.426`，`[APP]`）；换成纯噪声后 5 个种子的 min `pstd` 落在 `0.357–0.475`，所以带噪声的 H0 帧上界要放宽到 `0.52`，别拿 `0.48` 卡 T7。

### 9.3 上板验收（可判定）

| ID | 指标 | 方法 | 通过条件 |
|---|---|---|---|
| A1 | 实际采样率 | 注入 1 Hz 方波，数 100 s 内边沿 | `fs ∈ [499, 501]` Hz；否则用「高速采样 + 抽取」，见 §11.2 |
| A2 | 单步耗时 | GPIO 翻转 + 示波器，或 `esp_timer` 统计 1e4 步 | p95 ≤ 8 μs，max ≤ 20 μs |
| A3 | 帧计算耗时（不含采集墙钟） | 一帧起止时间戳 | `known` ≤ 5 s；`auto`（v2）≤ 15 s。**采集墙钟恒为 94.2 s，不可压缩**——这是信号时标，不是性能问题 |
| A4 | 与仿真一致 | `SELF_TEST` 注入 `vec_h1` 波形（`phase=0` 或 12 相位成组） | `detected==1`；改 `R×1.05` 后 `==0` |
| A5 | 虚警 | 输入端接地/屏蔽，连跑 200 帧 | Pfa ≤ 0.05，**须注明门限值**：`q_th=0.08` 时实测应≈0，用 `q_th_pfa5=0.347` 时名义 5% |
| A6 | 检测概率 | SNR −7.4 dB 注入，`theta` 随机 100 帧 | Pd ≥ 0.85 |
| A7 | 内存 | `heap_caps_get_minimum_free_size` | 峰值占用 ≤ 64 KB |
| A8 | 长稳 | 连续 24 h | 无复位，`ovf_cnt` 增量 = 0 |
| A9 | 零漂 | 短路输入，1 h | 每帧 `pstd` 漂移 < 20% |

**A3 的量级参考**：`[APP]` 在 PC 上 47100 点、三相位 `known` 模式实测 **0.15 s**（`analyze(known)` 1.513 s → 0.149 s，10×；见 `00-总览/性能优化与基准.md`），`auto`（FFT + 16 次单振子 + 三路）3.63 s → **0.92 s**（3.9×）；估幅另加约 2.6 s（180 路一次向量化，**这一项没变快**——它本来就摊满了数组，没有调用开销可摊）。ESP32 按 §9.3 A2 的 8 μs/步上限估，`3 × 47124 × 8 μs ≈ 1.13 s`，故 5 s 是宽松上限；真正卡时间的是采集墙钟。

**这 10× 不能搬到固件**：PC 的瓶颈是 numpy 每次调用的固定开销（每步 60–80 次调用 × ≈0.41 μs，浮点本身只占几纳秒），所以「少调用」能换 10 倍；C 的标量循环没有这种开销，ESP32 的 8 μs/步是**算术与访存**的真实成本，与 PC 的 0.15 s 没有可比性。固件侧优化只认 A2 的指令数，别拿 PC 的加速比当预期。

**A7 的 64 KB 不受本次重构影响**：上位机的提速靠「整帧驱动表 + 标量微内核」，两者都吃内存（§5.1）；固件是流式 + 4 KB `cos_q30` 表，峰值只随通道数与帧内 Poincaré 点数变（`N_BETA = 3`、150 点 → 数 KB 量级）。若 A7 超了，先查是不是照抄了上位机的预算表，而不是去压 `FRAME_N`——缩帧会直接破坏判据（< 48 周期即抖动）。

**A4 的相位条件**（最容易漏）：`SELF_TEST` 单次注入时若用随机初相，`A = 0.02` 的单振子只有 **26.6%** 的相位能越过阈值（§11.1），单帧测试有 73% 概率假失败。必须 `phase=0`（同相，`lam_eff = 0.740` 恰好越线），或按 `theta = 0°, 30°, …, 330°` 注入 12 帧、要求命中 ≥ 10 帧——后者同时在测三相位阵列的覆盖率，更接近真实使用。

**A4 的 `R×1.05`**：`R` 偏离 5% 时 `h1` 变为 0.021，频率失谐远超 ±0.1% 带宽，必须判「无」`[S2]`。这只是粗测门槛，工程验收按 **≤0.1%** 要求：`[APP]` 的频率选择带宽实测为 ±0.1%（判据 1e-2），接收端界面提示的「偏 5% 就判不出来」只是演示级说法，不可当作容差。

**A6 的 0.85**：`[LK]` 在 94.25 s 帧、三相位、`A=0.0302` 时给 Pd=1.00，理论覆盖率 100%（§11.1）。留 15% 余量给 ADC 与时钟抖动，属 `[SPEC]` 折减。若换到 `A=0.02`（−11 dB 同相），单振子 Pd 只有 0.46、三相位 0.80，`A6` 必然不达标——**两档 SNR 不能混着引用**。

### 9.4 不通过时的定位顺序

```
A4 失败 ──► 先查 T8（Poincaré 插值，含补角）→ 再查 T2（定点等价性）→ 最后查驱动
A6 偏低 ──► 先查 A1（采样率）→ 再查前置滤波器截止 → 最后查 betas 配置
A5 偏高 ──► 先查 §2.4 反模式（RF/电源）→ 再查 q_th 标定帧数
一律判「无」且 peak ≈ 0 ──► 不是算法问题，查 T11 与前置增益（§2.1），别改门限
```

按顺序查，不要跳步。历史教训：`[S5]` 的 0.77 假阈值是方法错误，不是硬件问题。

## 10. 错误处理

### 10.1 错误码

| 码 | 标识 | 触发 | 动作 | 恢复 |
|---|---|---|---|---|
| 0 | `OK` | — | 正常 | — |
| 1 | `ERR_ADC_TIMEOUT` | `acq_read` 超时 3 s | 丢弃当前帧，`drop_cnt++` | 自动重试 3 次后进 `ERR` |
| 2 | `ERR_RING_FULL` | 环形缓冲满 | 丢样，标记该帧作废 | 自动 |
| 3 | `ERR_OVF` | `ovf_cnt > 0` | 该帧不输出 0/1 | 下一帧自动清 |
| 4 | `ERR_PARAM` | 参数越界（编译期 + 运行期双检） | `HALT` | 仅复位 |
| 5 | `ERR_CALIB` | `CALIB` 帧数不足或方差异常 | 回退 `q_th_default` 继续 | 自动 |
| 6 | `ERR_RATE_MISMATCH` | 实测 `fs` 偏离 > 1% | 重算 `h1`/`ph_inc` 并重标 `q_th` | 自动；失败进 `HALT` |
| 7 | `ERR_ADC_SAT` | 连续 16 样本达满量程 | 日志告警，判决继续但标记不可信 | 增益调整后清 |
| 8 | `ERR_INPUT_SILENT` | 连续 `silent_n=5` 帧 `peak < q_peak_min` | **不输出 0/1**，日志报「输入静默/断线」 | 电平恢复即自动 |
| 9 | `ERR_FRAME_GAP` | 一帧 `miss > 0` 或 `drop_cnt > 0`（§8.4 规则 4） | `pstd` 照算但判决标记不可信，不进 ROC 统计 | 下一帧自动 |

**为什么 8 和 9 必须存在**：`pstd` 对这两类故障是**盲的**。断线时 `u ≡ 0`，系统仍在内驱作用下混沌振荡，`pstd ≈ 0.43`，与正常噪声帧（0.36–0.48）难分，判决只会安静地输出「无」；丢包补零时 `pstd` 反而被压低，容易假报「有」。两个方向都错，且都不报错——所以必须由输入电平与包完整性各自独立判定，不能指望统计量兜住。

### 10.2 日志约定

```
[E][<code>] <module> | frame=<id> | <detail>
[W] ...
[I] ...
```

- `E` 级必带错误码与 `frame_id`，便于与上位机 CSV 对齐。
- 禁止在中断上下文打印（`ESP_LOGE` 在 ISR 中会阻塞）。

### 10.4 运行期参数校验（对齐 `[APP]`）

上位机在点「开始发送 / 开始监听」时逐项校验，非法值弹窗拒绝启动；固件没有弹窗，必须走同一套规则并返回 `ERR_PARAM`。**这张表不是可选的**：少验一项，错误配置就会一路跑到帧末才以「判据异常」的形式暴露，定位成本高一个数量级。

| 参数 | 规则 | 违反时 |
|---|---|---|
| `omega` | `> 0` | `ERR_PARAM` → `HALT` |
| `fs` | `> 0`；与 `1/dt` 一致 | 同上 |
| `dt` | `> 0` | 同上 |
| `R`（`known` 模式） | `> 0` | 同上 |
| `R`（`hint` 模式） | 头包 `w_hint > 0`，缺失即拒绝 | 拒帧，日志「没有收到发送端的频率提示」 |
| `lam0` | `0 < lam0 < lam_c`（0.7335） | `ERR_PARAM` → `HALT` |
| `q_th` | `> 0` | 同上 |
| 帧样本数 `n` | `≥ 15080`（48 周期） | 拒帧，记 `ERR_FRAME_GAP` |
| `sigma` | `≥ 0` | 仅上位机侧存在 |
| 回放倍率 | `> 0` 且 `≤ baud/(40·fs)` | 超限则降到上限并告警 |

上位机的校验集中在 `TxApp.params()` / `RxApp.params()`，非法时抛 `ValueError` 并弹窗；固件实现 `det_params_check()` 时逐条对应，报告首次失败的字段名与实测值，不要只回一个笼统的错误码。

## 11. 扩展限制

### 11.1 物理硬限制（不可通过软件绕过）

**初相盲区**。单振子的有效激励为

$$\lambda_{\text{eff}} = \sqrt{\lambda_0^2 + A^2 + 2\lambda_0 A\cos\theta} > \lambda_c$$

`theta` 落在阈值外则无论幅值多大都判「无」。覆盖率随 `A` 变化：

| SNR（`sigma=0.05`） | `A` | 单振子 `theta` 上限 | 单相覆盖 | 三相位覆盖 | 来源 |
|---|---|---|---|---|---|
| −11.0 dB | 0.0199 | 47.9° | 26.6% | **79.9%**（漏 20%） | `[APP]` 计算 |
| −7.4 dB | 0.0302 | 64.5° | 35.8% | **100%** | `[APP]` 计算 |
| −3.0 dB | 0.0501 | 76.3° | 42.4% | 100% | `[APP]` 计算 |

三相位全覆盖的临界点是 `2θ ≥ 120°`，解出 **`A ≥ 0.0263`（`SNR ≥ −8.6 dB`）**。注意 `−9 dB` 只有 **97.1%**，不是 100%——差这一档时，`theta` 恰好落在盲区的帧会被稳定漏掉。

**推论**：`A ≈ 0.02` 是「刚好越线」（`lambda_eff = 0.740`，余量仅 0.0065），相位随机时单振子 Pd 被封在 0.46 一线、三相位 0.80。**不要宣称 −11 dB 下三相位满覆盖**；要满覆盖就必须 `A ≥ 0.0263`。

**其他硬限制**：

| 限制 | 数值 | 后果 |
|---|---|---|
| 帧长下限 | 48 周期 = 30.2 s | 更短则 `pstd` 抖动跨门限 `[LK]` |
| 频率选择带宽 | ±0.1% | `R` 偏差超 0.1% 即失谐 `[S2]` |
| 观测窗 | 94.2 s / 帧 | 不可压缩，是信号时标 |
| 判决延迟 | ≥ 1 帧 = 94.2 s | 无实时性可言，见 §11.2 |

### 11.2 平台限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| ESP32 内置 ADC 标称 12 bit，实测 ENOB ≈ 9.5 bit | 达不到论文的 12 bit 条件 | ADC 位数对判决不敏感（8 bit `pstd=2.26e-3` vs 12 bit `2.22e-3`，差 2%）`[LK]`，故可用；论文级复现换 ADS1256。**引用该结论必须带前提**：实验用的是按帧峰值自适应的满量程，与固定量程 ADC 不等价（§8.4） |
| `adc_continuous` 低采样率可能不支持 500 Hz | 实际 `fs` 偏离设定 | 退化为 8 kHz 过采样 + 16 点均值抽取到 500 Hz；必须用 A1 标定 |
| UART 回放带宽有限 | 460800 下 ×10 实时已是上限（19.5 KB/s），上位机「尽快」模式要 488 KB/s | 联调固定「实时×10」；大批量回放走 SD 卡或本地 ADC，不要试图压 UART |
| 无双精度 FPU | `double` 走软件模拟，慢 ~100× | 全链路定点；仅 `pstd` 后处理用 `float` |
| 单块 DRAM 上限 ~160 KB | 无法缓存整帧 188 KB | 流式架构，§5.1 |
| WiFi/BT 与 ADC2 冲突、电源污染 | 检测失效 | 编译期关闭 RF |
| 时钟精度 40 MHz 晶振 ±10 ppm | 150 周期累积相位误差 1.5e-3 周期 | 可忽略；但 `fs` 实际值仍须标定 |

| 内置 ADC 的 1/f 拐点 | 若拐点 > 0.1 Hz，需加高通 |
| `cos_lut` 精度对 `pstd` 的影响 | `[S5]` 的定点化未覆盖 cos（用双精度），本规格改用 1024 项 LUT + 线性插值，**新增误差源，必须验证** |

### 11.4 v2 扩展（明确不在本规格内）

| 扩展 | 前置条件 |
|---|---|
| 扫 `R` 自动对频 | 上位机已实现 `[APP]`：`fft_guess()`（Hann + 8× 补零 + 对数抛物线，频段 0.3–5.0 Hz，初值误差 ~0.002%）+ `scan_R()`（±1% 内 0.5%/格粗扫 5 点 → 最优点 ±0.25% 内 0.05%/格细扫 11 点 → 三点抛物线，共 16 次单振子）。PC 端整帧 3.63 s → **0.92 s**（其中 `scan_R` 2.05 s → 0.75 s，2026-11-26 重构；见 `00-总览/性能优化与基准.md`），`R̂` 端到端误差 −0.025%。移植到 ESP32 需 16×47124 ≈ 7.5e5 步，按 8 μs/步 ≈ 6 s，**算力可行但不能与采集并行**，须等整帧收完再扫。频段内无可辨谱峰时上位机返回「无法判定」而非猜一个 `R`——固件移植必须保留这个分支，不得退化成默认 `f0` |

### 12.2 四条最易犯的禁令（再列一次）

1. **不得引入 `ν`**。旧称已废弃，正确的量是 `R`；代码里出现 `nu` 即为错误。
2. **末态组合不得用 `qadd` 连加**。必须 `int64` 累加后一次移位（§4.4）。
3. **不得按步数取整取 Poincaré 点**。必须 DDS 相位溢出 + 线性插值（§4.5），否则压掉 4 个量级。
4. **插值权重不得取「跨线后余量」**。`frac` 是溢出后的余量，权重是它的补角 `(PH_INC - frac)/PH_INC`；写反后周期态 `pstd` 从 `3.2e-6` 变成 `1.2e-2`（§4.5 对照表），症状与第 3 条几乎相同，极易误诊。

| §11.3 的 `[TODO]` 项无法实测 | 只能标 `[TODO]`，**禁止**填推测值并去掉标记 |
