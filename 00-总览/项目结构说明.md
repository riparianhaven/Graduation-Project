### 为什么这次敢把文档分进子目录（推翻上午的判断）

上午版本说「文档必须留根目录，否则断链」，那是**过于保守**的结论。复核工具链后发现两条关键事实：

1. `serve_index.py` 的 `ROOT` 是**项目根**，`do_GET` 对任意子路径的 `.md` 都实时渲染——子目录文档照样能访问。
2. `build_static.py` 用 `rel.count('/')` 计算回跳，副本生成在**源 md 旁边**——它天生支持分层。

于是这个下午做了受控重组：先用 dry-run 预览 543 处引用改写，把 57 个源文件备份到 `.workbuddy/backup/reorg_20261123/`，再批量改链 + 移动。**结果：当时 765 条本地引用 0 失效；阶段 4 交付后复校为 850 条 0 失效**（新增 06-阶段四 与 learn/4）；阶段 5 交付后再复校，见文末校验记录。

## 三、分类规则

| 判据 | 归入 | 说明 |
|---|---|---|
| **导航与全局说明** | `00-总览/` | 阅读路线、结构说明、主清单、技术路线、环境说明 |
| **按阶段的成果** | `01-阶段一/` `02-阶段二/` `03-阶段三/` | 每份「问题回答 + 过关产出」成对，附支撑材料 |

| **被主流程执行** | `tools/` | 一改就可能让站点或复现失效，集中管理 |
| **被文档当资源引用** | `assets/` | 搬动只需改引用，不改逻辑 |
| **验证行为、不参与交付** | `tests/` | 可随时运行不影响产物 |
| **程序自动生成** | `复现输出/` | 可再生，只读对待 |
| **教学 / 可运行实验** | `learn/`、根目录 `复现-2-*.ipynb` | 前者按阶段分节，后者是主交付 |
| **书籍化复现** | `c2-jupyterbook/`、`s2-jupyterbook/` | 两套独立 jupyter-book 工程 |
| **纯数据与题录** | `文献/` | 与文档解耦，可整体搬迁 |
| **工具自建、不可重建** | `.venv` / `.workbuddy/` | 前者可重建但不该动，后者含记忆，禁止删除 |

- `tools/serve_index.py` / `tools/build_static.py` / `tools/run_ipynb.py`：`ROOT` 均上跳一级到项目根，不因文档分层改变。
