2.4 反模式（违反则指标不可复现）

  1. 禁止使用 ADC2：ADC2 与 WiFi 共用仲裁器，开 RF 时读数失效。只能用 ADC1。
  2. 检测期间关闭 WiFi/BT：RF 突发电流在 3.3 V 轨上产生 > 50 mV 波动，直接进入 1.59 Hz 带内。
  3. ADC 源阻抗 < 10 kΩ：ESP32 ADC 采样保持电容充电不足会引入非线性。前置放大输出串 1 kΩ + 100 nF 到地。
  4. 硬件高通截止 ≥ 0.1 Hz：抑制传感器直流偏置与 ADC 1/f 漂移；截止频率必须远低于 f0 = 1.5915 Hz。
  5. 模拟地与数字地单点连接，模拟部分加屏蔽罩。

3.4 噪声类型（[APP] 已实现，固件无需实现）

上位机可注入两种噪声，用 make_noise(alpha) 生成：

alpha类型实现谱形
0白噪rng.standard_normal平坦
11/f 色噪rfft 后按 f^(-alpha/2) 加权、去 DC、再归一化到单位方差低频抬高

关键：色噪只改谱形，不改 σ 口径——归一化后每样本标准差仍是 sigma·sqrt(h1)。所以 §3.1 的 A、lam_eff、q_th 全部沿用。固件侧不需要生成噪声，但 CALIB 必须在两种谱形下都验一遍：真实磁通门的 1/f 拐点若落在 1.6 Hz 附近，白噪下标定的 q_th 会偏乐观（[TODO]）。

两套 SNR 口径，别混着引用：力口径按 lam0 归一（SNR = 20lg(A/lam0)，配 sigma 定 A），每样本口径 SNR_E = 20lg(A/(σ√2))。两者差 10lg h1，本链路 h1 = 0.02 → −17 dB。所以界面读到 −7.4 dB 的那一帧，每样本是 +9.6 dB，波形图上本该看得见正弦；反之 −15 dB（SNR_E）的框架演示里看不到波形也是正常的。不要用「波形看不出来」判信号没发出去，判据只有 pstd 与相干投影。

4.2 乘法与舍入

// 状态 × 状态 -> 状态 (Q6.12 × Q6.12 -> Q6.12)
static inline int32_t qmul(int32_t a, int32_t b) {
    return (int32_t)(((int64_t)a * b + (1 << 11)) >> 12);
}

// 状态 × 系数 -> 状态 (Q6.12 × Q0.30 -> Q6.12)
static inline int32_t qmul_coef(int32_t a_q12, int32_t c_q30) {
    return (int32_t)(((int64_t)a_q12 * c_q30 + (1LL << 29)) >> 30);
}
  • 两个插件的中间积都必须 int64_t：qmul 的上界 131071² = 1.7e10，qmul_coef 的上界 131071 × 2^31 = 2.8e14，均超 int32。
  • qmul_coef 的值域要求 |a_q12| ≤ 2^17（即状态 ≤ 32.0），与 Q6.12 范围一致。
  • 舍入为「加半后算术右移」，允许 ±1 LSB 偏差；不要求 round-half-away-from-zero。
  • qadd / qsub 为饱和加，见 §4.3。但 §4.4 的末态组合不得用 qadd，见该节说明。

4.4 单步积分（固定字段，实现必须逐项对应）

方程为一阶化系统 x' = y、y' = -0.5y + x³ - x⁵ + lam0·cos(τ) + u。

    x2 = qmul(xx, xx)

    x5 = qmul(x2, x3)                       // 三次乘, 禁止 pow()
    return qsub(qsub(qadd(x3, d), x5), qmul(HALF_Q12, yy))

int64_t sx = (int64_t)k1x + 2LL*k2x + 2LL*k3x + k4x;
int64_t sy = (int64_t)k1y + 2LL*k2y + 2LL*k3y + k4y;
x = qadd(x, (int32_t)((sx * H6_Q30 + (1LL << 29)) >> 30));

其中 HH·k 表示 qmul_coef(k, HH_Q30)，H1·k 表示 qmul_coef(k, H1_Q30)。

为什么末态不能复用 qmul_coef：sx 的量级上界为 6 × q_max = 786426，超出 qmul_coef 的入参值域（≤ 2^17），必须先 int64 累加再内联移位。用 qadd 连加则会中途饱和——这正是「每步都少一点、最后判据崩掉」的典型来源。

三条硬性禁止（违反即 [S5] 记录的 0.77 假阈值重演）：

  1. k2/k3 必须用 h1/2。旧实现误用整步 h1，积分精度退化到 RK2，相变点被推到 0.77 [S5]。
  2. x^5 用 x2=x*x; x3=x2*x; x5=x2*x3，三次乘。禁止 pow()，禁止 x*x*x*x*x 串联（尾两个乘法会越界）。
  3. u 只作为 drv 的独立加项，不得并入 lam0（lam0 + u 是错误写法，会改变 lam_eff 的物理含义）[S5]。

cos_q30 规格（这是 [S5] 未覆盖的新误差源）：

项值
表长1024 项，覆盖 [0, π/2)，Q0.30
索引idx = ph >> 22；frac = (ph >> 6) & 0xFFFF
插值lut[idx] + ((lut[idx+1] - lut[idx]) * frac >> 16)
象限折叠用 ph 的最高两位选择符号与镜像

折算到激励5e-6 × 0.72 = 3.6e-6，约为 Q6.12 一个 LSB 的 1.5%，可忽略

表占 1024 × 4 B = 4 KB，放 const 段（flash），不占 DRAM。若 §9.2 T9 不通过，先试 4096 项表，再试 CORDIC，不得改用 cosf()（无硬件双精度，且破坏跨平台一致性）。

4.5 相位累加器与 Poincaré 采样

用 DDS 式满量程相位：uint32_t ph，2^32 ≡ 2π，每步 ph += PH_INC，溢出即跨过一个载波周期。

uint32_t prev = ph;
ph += PH_INC;
if (ph < prev) {                    // 本轮跨过 2πk
    uint32_t frac = ph;             // 跨线**后**的余量, 0..PH_INC-1
    // 权重 = 跨线**前**走过的步内比例 = 1 - frac/PH_INC, 必须取补角
    uint32_t before = PH_INC - frac;
    int32_t alpha_q30 = (int32_t)((uint64_t)before * 1073741824ull / (uint64_t)PH_INC);
    poc_val = qadd(x_prev, qmul_coef(qsub(x, x_prev), alpha_q30));
    poc_push(poc_val);
}
x_prev = x;                          // 每步更新, 供下一次跨周期插值

alpha_q30 的分子 before × 2^30 最大 1.37e7 × 1.07e9 = 1.47e16，必须用 uint64 中间量（uint32 会截断）。结果落在 [0, 2^30]，正是 qmul_coef 要求的 Q0.30 值域：before = PH_INC（恰在步末跨线）时 alpha_q30 = 2^30，乘积精确复现 x。若 qmul_coef 的入参上界写死为 2^30-1，需在此钳一位，误差 < 1 LSB。

补角必须取，这不是可选的写法差异。 frac 是跨线后的余量，截点位于 tau + (1 - frac/PH_INC)·h1；直接把 frac/PH_INC 当权重，截点会落到 tau + (frac/PH_INC)·h1，即从跨线处反向偏出 |1 - 2·frac/PH_INC|·h1，最大一个整步，且偏差随 frac 在 [0, h1] 内摆动。同一段浮点 RK4 只换权重实测 [APP]：

状态frac 口径（kernel 正确）余量口径（本节的常见错法）按步数取整
混沌 lam=0.724.303e-14.308e-14.612e-1
临界 lam=0.73353.771e-13.768e-14.017e-1

混沌态两种写法看不出差别（差 0.1%），周期态差 3.6 个量级——所以这个错在 T5/T7 上不会暴露，只在 T4/T8 上翻车，而且症状与「按步数取整」几乎一样（都是 1e-2 量级），极易误诊为「插值没做对」而反复改 idx。定位时直接对照本表。

与 tools/kernel_src.py 的对应：内核写 frac = (2π·idx − τ)/h1 并 clip 到 [0,1]，即「跨线前比例」，与本节 before/PH_INC 逐位等价（idx 就是本节的溢出计数）。改内核口径必须同步改本节，否则 T8 与 [S5] 对不上。

禁止按步数取整判周期（如 if (n % 314 == 0)）。按步数取整会把周期态 pstd 从 3.2e-6 抬到 3.4e-2，压掉 4 个量级动态范围 [S2]。

PH_INC = 13671306 的取整误差为 +0.5 LSB（精确值 13671305.512）/步，折算 7.1e-10 rad，150 周期累积 5.4e-6 周期，可忽略。

4.6 pstd 计算

// poc 点以 Q6.12 存, N = 实际 poc_cnt（正常帧 = poc_pts = 75，只取后 50%）
int64_t s1 = Σx;                    // Q6.12, |x|≤2, N=75 -> ≤ 6.2e5
int64_t s2 = Σ(x*x);                // Q8.24, |x|≤2, N=75 -> ≤ 5.1e9 (int64 安全, 不必移位)
float mean    = (float)s1 / (float)N / 4096.0f;        // 2^12
float mean_sq = (float)s2 / (float)N / 16777216.0f;    // 2^24
float var = fmaxf(mean_sq - mean * mean, 0.0f);
pstd = sqrtf(var);
  • 统计后处理用 float：仅每帧 1 次，不影响逐样本确定性。
  • s2 无需右移预处理：N=75、|x|≤2 时上界 5.1e9，远低于 int64 上限。若 N > 2e6 才需要分段累加。
  • 只有 s1/s2 两个累加器，无点集存储——这是流式架构成立的前提。
  • pstd 的确定性由 §4.4 的定点积分保证，不由统计后处理保证。
  • 分母必须用实际 poc_cnt，不得写死 POC_PTS：帧被截断、ERR_OVF 提前收尾、回放 n < FRAME_N 时点数会少，用常量做分母会系统性压低 pstd（分母偏大 → 方差偏小），表现为「短帧更容易判成有目标」。
  • 定点地板：12 位小数位下周期态 pstd 的地板是 2.7e-3（F=12）/ 7.6e-3（F=10），来自每步对驱动项与状态的舍入；浮点同一条件是 3.2e-6。门限 0.08 离地板仍有 30 倍余量，判决不受影响，但浮点值不能当固件指标（§9.2 T8）。

pstd 不能用来判断线/静默。 u ≡ 0 时系统只剩内驱，而 lam0 = 0.72 < lam_c → 仍处于混沌态，pstd 是 0.43 量级（三路实测 [0.431, 0.527, 0.572]，[APP]），不是 0。也就是说：传感器断线、ADC 断流、前置放大掉电，在 pstd 上看起来与「纯背景噪声」几乎一样（噪声帧 0.36–0.48），只会安静地判「无」，不会报错。真正的 pstd 塌缩是另一种情形：lam0 越过 lam_c（lam0=0.74 时三路 3.0e-6 / 2.4e-5 / 4.0e-6）或定点字长不足导致轨迹锁死在少数格点（F=4 时全程 pstd ≈ 0）。两种情况必须用不同判据区分：

现象物理含义判据处理
pstd ≈ 0.43、peak ≈ 0输入静默（断线/断流）输入电平，见 §10.1 ERR_INPUT_SILENT不输出 0/1
pstd < q_th_min定点塌缩或 lam0 越界q_th_min = 1e-7ERR_OVF / ERR_PARAM

5. 数据流与任务模型

5.1 流式架构（不缓存整帧）

一帧 47124 样本以 int16 缓存要 92 KB，仍超出本工程给检测链留的 64 KB 峰值预算。因此必须流式：

ADC DMA ──► on_sample(u) ──► duffing_step(3 路) ──► poc_push ──► 滑动 pstd 累加
                                                                    │
                                          帧末 ──► pstd ×3 ──► min() ──► 判决

内存占用与帧长无关：3 × (状态 8 B + 累加器 16 B) + 环形缓冲。[SPEC] 峰值 ≤ 64 KB。

上位机的「驱动表预算」不可照搬（2026-11-26 提速改造，见 00-总览/性能优化与基准.md）：PC 侧把 lam·cos(τ+β)+s 在循环外整列预算成 3 条 Python float 列表（单列 3 × 47124 个 float，含对象开销约 4.5 MB），换来 11 倍速；固件上这条路既无必要也不可行——cos_q30 是 1024 项 LUT（4 KB，flash），驱动项每步实时算两个 qmul 即可。固件若照抄「整帧预存驱动项」，47124 × 3 路 × 4 B ≈ 566 KB，直接顶穿 64 KB 预算，A7 必挂。

5.2 双核分工

核任务优先级职责
0acq_task8adc_continuous_read → 写 ringbuf，只做搬运，不做算术
1proc_task6从 ringbuf 取样本 → duffing_step ×3 → 帧末判决

丢样判定：acq_task 写入时若 ringbuf 满，drop_cnt++；一帧内 drop_cnt > 0 则该帧作废（时间轴不连续，Poincaré 点失效）。

与上位机的对应关系（[APP]）：_recv 线程只做「收包 → 按 seq 写入定长数组 → 凑齐提交」，与 acq_task 同职责，不含任何算术；_worker 线程从队列取整帧、算三路 pstd、出判决，与 proc_task 同职责；_drain 每 100 ms 取结果刷界面，与 uplink 同职责。上位机用两个线程而不是一个，是因为 recvfrom 会阻塞而判决要跑 0.15 s（优化前 1.5 s，见 00-总览/性能优化与基准.md）；固件里对应的是两个任务 + ringbuf，理由相同：采集绝不能被判决阻塞。若把判决写进采集回调，94 s 的帧会丢样，drop_cnt 一路涨，帧帧作废。

5.4 帧边界与判决

帧开始: 清 s1, s2, poc_cnt, ovf_cnt
每样本: duffing_step ×3 → 每路独立 poc 累加
        poc_cnt += 1
        if (poc_cnt > POC_SKIP)  { s1 += x; s2 += x*x; }    // POC_SKIP = 75
poc_cnt == POC_TOTAL 时: 计算 3 个 pstd（各用 75 个点）
帧结束: p = min(pstd[0], pstd[1], pstd[2])
       detected = (p < q_th)

POC_SKIP = 75 即 burn_frac = 0.5：前 75 个 Poincaré 点丢弃，只用后 75 个。不要改成「帧末统一丢弃」——那需要缓存全部 150 个点，破坏流式架构。

三路取 min 是判决用法；测量带宽或估幅时必须单路（beta=0），因为三路取 min 会把别的振子在锁频态的伪相变捞进来 [S2]。

四条帧边界约束（固件与 [APP] 必须一致，否则「两边都算对了但结论不同」）：

  1. 参数只在帧边界生效。上位机的做法是主线程每 100 ms 把输入框刷进 self.cur 快照，工作线程每帧开头读一次。改到一半的 R/lam0 会让同一帧前后步长不一致，h1 不再恒定，Poincaré 截面失去意义。固件同理：NVS 写入只置「待生效」标志，proc_task 在帧末才切换。
  2. 新帧开始即丢弃残帧。上位机收到头包直接 self.buf = FrameBuf(obj) 覆盖旧的，不排队、不拼接。固件收到 H 亦须立即复位装配缓冲并 drop_cnt++。
  3. 数据包必须校验 frame。上位机对 frame 与当前头包不符的包直接丢弃（丢了头包的残包）。只按 seq 写而不校验 frame，会把上一帧的尾包写进新帧，制造「看似完整、实则错位」的帧。
  4. 积分步数由样本数决定。steps = n（因为 h1 = R·dt 固定时 n_cycles = n·h1/2π 反推回来恰好是 n）。本地采集时 n = FRAME_N；回放时以头包 n 为准，不得写死 47124——上位机默认 94.2 s 只给 47100 点，写死会多积 24 步（尾部样本早耗尽，驱动归零），pstd 偏低。回放还须满足 §9.1 的 n ≥ 15080。

内核形态（2026-11-26 重构后）：simulate_seq 内部按振子数分两条路径——m ≤ 32 走微内核（每通道纯标量 RK4），m > 32 走向量路径（沿通道维一次算 m 路）。两条路径对同一问题给出逐位相同的 pstd（测试钉在 m = 32/33 边界），签名与 simulate_fixed_seq 都未变。所以：导出向量不用关心它走哪条路径；固件实现对应的是 §4.4 的单步字段，与路径无关——两条路径执行的是同一套 k1..k4 与同一条末态组合式。

数值一致性验收（本仓库做法，固件侧可直接借用）：浮点侧不比 allclose，而是对 pstd/mx/Poincaré 点矩阵取 sha256 逐位比对（tests/golden/kernel_ref.json），因为混沌态下 1 ulp 的差会被指数放大成可见差异——容差在这里既太松又太严。固件侧同理：定点是全整数确定性运算，同输入必须逐位复现，见 §9.1 L2。

浮点 simulate_seq 也可以读，但只用于「趋势是否一致」的旁证：指标与容差一律以 simulate_fixed_seq（同一 F）为准。原因是 12 位小数位下周期态 pstd 地板是 2.7e-3，浮点是 3.2e-6，拿浮点当基线会得到「正确实现也不达标」的结论（§9.2 T8/T9）。

8.4 下行联调格式（link_ingest，v1 可选）

与 [APP] 的 UDP 协议同构，只把传输层从 UDP 换成 UART（检测期间禁 RF，§2.4）。三类包统一 4 字节魔数 WBDX + 1 字节类型：

包类型载荷长度
头HUTF-8 JSON：v, frame, n, fs, w_hint, amp, sigma, alpha, snr_db, has_sig, has_noise, duration, phase, ts, scale, t0, sig_t0, sig_dur, sig_epoch, cov≤ 512 B
数据Dstruct "<4scIIIf>"（魔数 / 'D' / frame / seq / nseq / fs）+ int16 小端样本21 + 2·1024 = 2069 B
尾TUTF-8 JSON：{frame, sent, nseq}≤ 64 B

协议 v = 2 起样本是 int16（v = 1 是 float32，已废弃）：满量程对应 ±1.0，scale = 32768 随头包下发，1 LSB = 3.05e-5。选它是因为 ESP32 的 ADC 本来就是整数计数——收发两端从此都在整数域里说话，省掉一次浮点解析，包长也从 4117 B 减到 2069 B。

一帧 = 1 个 H + ceil(n/1024) 个 D + 1 个 T。n = 47124 时是 47 个数据包、约 95 KB（n = 47100 时 46 个包）。

连续发送与目标窗（v2 新增）：上位机启动后一直发、不自动停，帧号从 0 单调递增、没有"总帧数"；目标可以在发送过程中随时附加，所以头包里必须带四个时间字段——t0（本帧首样本的会话绝对时间）、sig_t0/sig_dur（目标窗起止）、cov（本帧覆盖率）。固件侧必须用同一套 window_coverage() 口径自己重算 cov，不能直接信 cov：这是唯一能发现"发送端以为在发目标、固件却当背景帧"的办法。窗口不对齐帧，所以每隔一段时间必然出现 0 < cov < 1 的帧——这类帧既不算 Pd 也不算 Pfa，只计数。

装配规则（与 FrameBuf 逐条对齐，缺一条就会出现「两边都算但结果不同」）：

  1. 头包开新帧：收到 H 立即丢弃未装配完的旧帧，不排队、不拼接（§5.4 约束 2）。
  2. 按 seq 定位：写入 buf[seq·1024 : …]；重复 seq 直接丢弃（UDP 回环会重复，UART 重传也会）；frame 与当前头包不符的包丢弃。
  3. 尾包提交：收到 T 即提交，不等 n 点齐——尾包先到说明发送端已发完，缺的就是丢了。
  4. 缺包补零并标记：got < n 时缺口保持 0，miss 计入日志。上位机补零后照算，固件必须额外标记该帧不可信（ERR_FRAME_GAP，§10.1）：补零会压低 pstd，把「丢包」伪装成「检测到」，方向恰好是危险的那一侧。
  5. 超时丢弃：3 s 内未凑齐 → 丢帧，drop_cnt++。

样本换算：线上是 int16（LSB = 1/32768 = 3.05e-5），内部是 Q6.12（LSB = 1/4096 = 2.44e-4），换算就一条算术右移：

int32_t q_q12 = ((int32_t)q_i16) >> 3;      /* 32768/4096 = 8，算术右移保符号 */

所以线上分辨率比内部格式细 8 倍，线上量化不构成瓶颈，瓶颈仍在 Q6.12。对 A = 0.0199（int16 652 LSB → Q6.12 82 LSB）、每样本噪声 29 LSB 的信号，量化损失 < 1%，可忽略——但不要把这条链路当成「ADC 量化仿真」：make_frame(adc_bits=…) 的满量程是按本帧峰值自适应的（fsr = 4·max|rx|），与固定量程 ADC 不是一回事，两者混用会得出「8 bit 也够」的错误结论（§11.2 的位数敏感性结论必须带这个前提引用）。

带宽预算（决定 replay_mult_max）：

回放倍率数据率UART 最低波特率（8N1）可行性
×1（实时）1.0 KB/s10 kbaud任意波特率
×109.8 KB/s98 kbaud115200 够用；460800 更宽裕
×250（上位机「尽快」）244 KB/s2.4 Mbaud不可行，改用 SD 卡或本地 ADC

上位机「尽快」模式每包只隔 2 ms，是给回环 UDP 用的；UART 没有这个带宽。联调时把发送节奏设成「实时×10」，两侧才跑得动。换成 int16 后 ×10 只要 98 kbaud（float32 时代是 195 kbaud），115200 就从"不够"变成了"够"。

w_hint 的使用边界：头包里的 w_hint 是发送端的 omega，属联调旁路。固件 v1 只接受 known 模式（R 由 NVS 或命令给）；hint 只允许联调脚本用来对表，不得进入正式判决流程——那等于把待测量当作已知量，检测本身就没有意义了。上位机界面上把 hint 标为「跟随发送端」并附说明，就是防止误用。

A3 的量级参考：[APP] 在 PC 上 47100 点、三相位 known 模式实测 0.15 s（analyze(known) 1.513 s → 0.149 s，10×；见 00-总览/性能优化与基准.md），auto（FFT + 16 次单振子 + 三路）3.63 s → 0.92 s（3.9×）；估幅另加约 2.6 s（180 路一次向量化，这一项没变快——它本来就摊满了数组，没有调用开销可摊）。ESP32 按 §9.3 A2 的 8 μs/步上限估，3 × 47124 × 8 μs ≈ 1.13 s，故 5 s 是宽松上限；真正卡时间的是采集墙钟。

这 10× 不能搬到固件：PC 的瓶颈是 numpy 每次调用的固定开销（每步 60–80 次调用 × ≈0.41 μs，浮点本身只占几纳秒），所以「少调用」能换 10 倍；C 的标量循环没有这种开销，ESP32 的 8 μs/步是算术与访存的真实成本，与 PC 的 0.15 s 没有可比性。固件侧优化只认 A2 的指令数，别拿 PC 的加速比当预期。

A7 的 64 KB 不受本次重构影响：上位机的提速靠「整帧驱动表 + 标量微内核」，两者都吃内存（§5.1）；固件是流式 + 4 KB cos_q30 表，峰值只随通道数与帧内 Poincaré 点数变（N_BETA = 3、150 点 → 数 KB 量级）。若 A7 超了，先查是不是照抄了上位机的预算表，而不是去压 FRAME_N——缩帧会直接破坏判据（< 48 周期即抖动）。

A4 的相位条件（最容易漏）：SELF_TEST 单次注入时若用随机初相，A = 0.02 的单振子只有 26.6% 的相位能越过阈值（§11.1），单帧测试有 73% 概率假失败。必须 phase=0（同相，lam_eff = 0.740 恰好越线），或按 theta = 0°, 30°, …, 330° 注入 12 帧、要求命中 ≥ 10 帧——后者同时在测三相位阵列的覆盖率，更接近真实使用。

A4 的 R×1.05：R 偏离 5% 时 h1 变为 0.021，频率失谐远超 ±0.1% 带宽，必须判「无」[S2]。这只是粗测门槛，工程验收按 ≤0.1% 要求：[APP] 的频率选择带宽实测为 ±0.1%（判据 1e-2），接收端界面提示的「偏 5% 就判不出来」只是演示级说法，不可当作容差。

A6 的 0.85：[LK] 在 94.25 s 帧、三相位、A=0.0302 时给 Pd=1.00，理论覆盖率 100%（§11.1）。留 15% 余量给 ADC 与时钟抖动，属 [SPEC] 折减。若换到 A=0.02（−11 dB 同相），单振子 Pd 只有 0.46、三相位 0.80，A6 必然不达标——两档 SNR 不能混着引用。

9.4 不通过时的定位顺序

A4 失败 ──► 先查 T8（Poincaré 插值，含补角）→ 再查 T2（定点等价性）→ 最后查驱动
A6 偏低 ──► 先查 A1（采样率）→ 再查前置滤波器截止 → 最后查 betas 配置
A5 偏高 ──► 先查 §2.4 反模式（RF/电源）→ 再查 q_th 标定帧数
一律判「无」且 peak ≈ 0 ──► 不是算法问题，查 T11 与前置增益（§2.1），别改门限

按顺序查，不要跳步。历史教训：[S5] 的 0.77 假阈值是方法错误，不是硬件问题。

11.1 物理硬限制（不可通过软件绕过）

初相盲区。单振子的有效激励为

theta 落在阈值外则无论幅值多大都判「无」。覆盖率随 A 变化：
