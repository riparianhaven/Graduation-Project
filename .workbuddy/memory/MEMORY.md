## 数值定论（2026-11-24 定案，改动前先读）
- **ν 不是输入参数，是 ω/R 的别名**。待测 ω 未知时不必预设 ν：扫 R 到相变点，那一点
  的 R 就是 ω。代码里已无 `nu=omega/R`；唯一内核 `simulate_seq(sig, R, dt, lam, beta)`。
- **无信号标定走同一内核**：`SIG0=np.zeros(1)` + `R0=1.0`（h1=dt，两轴重合）。
- **真实 λ_c ≈ 0.7335**（0.7332 混沌 / 0.7336 周期；0.7334 是刀锋 → 报带不报点）。
  旧说 0.735/0.736 偏高，主因粗网格 0.005 + 短时窗。
- **两条数值红线**：① Poincaré 必须精确落在 τ=2πk 做线性插值（按步数取整会把周期态
  pstd 从 3.2e-6 抬到 1.5e-2，压掉 3.5 个量级）；② λc 附近瞬态长达上千秒（T=400 读数全
  错，T=3000 才收敛）——据此写出的「跃变带内混沌/周期交替」是伪结论。
- 动态范围拉开后：伪相变（R≠ω）pstd 最低只到 3e-2，真共振 3e-5，差 3 个量级；门限从
  0.08 收紧到 1e-3 后扫 R 只剩真值。**相干指数 ρ 分不开**（0.9954 vs 0.9931）。
- **频率选择带宽只有 ±0.1%**（判据 1e-2，三频 10/7.3/3.7 完全一致 = 由阻尼与恢复力
  决定）。旧「±0.5%」是 600 s 短窗，长窗引用用 ±0.1%。带宽测量必须**单路 β=−120°**，
  三振子取 min 会把伪相变捞进来（0.20% 糊成 0.55%）。
- **全域穷举必漏**：4.9%/格时最近格点偏 0.88%。必须先 FFT 给初值（误差 ≤0.005%），
  再在 ±1% 内按 0.05%/格细扫；三频最终误差 ≤0.012%（抛物插值）。
- 论文里要如实写的不利结论：表 2 与步骤 3 不自洽（R=10→h1=1 s→每周期 6.28 步→RK4
  发散）；三路 λ 对不上同一 C_trig（极差 0.0086）→ γ 低估 31%、θ 偏 18.3%。

## ★[8] 性能与基准（2026-11-26）
- **瓶颈＝numpy 的每次调用开销，不是浮点**。原内核每步 60–80 次 ufunc（3 元数组上一次
  ≈0.4 μs），47124 步 × m=3 = 1.45 s，真正的浮点只占几纳秒。证据：3 路阵列 1.448 s vs
  3 次单路 0.40 s；m 16→180 总耗时只涨 1.7 倍。
- **结构**：`m ≤ 32` 走**微内核**（驱动表按列预算成 Python float 列表 + 纯标量 RK4）；
  `m > 32` 走向量路径（`np.abs(x, out=ab)`、`h12/h16` 外提、`ascontiguousarray`）。
  阈值 32 来自实测交叉点 ≈40。两条路径**逐位相同**（有测试钉在 m=32/33 边界）。
- **三条不能碰的红线**：① `x**3` 不能换 `x*x*x`（200000 样本里 51845 个位模式不同，
  最大差 2.8e-14）；CPython `float.__pow__` 与 `np.power` 逐位相同。② `np.cos` 与
  `math.cos` 在 float64 上逐位相同、且与数组形状无关 → 驱动项可以搬出循环。
  ③ `p.std(axis=0)` 归约顺序跟内存布局有关：`.T` 出来的 F 序比 C 序差 1 ulp，
  微内核必须 `ascontiguousarray`。
- **速度**（本机）：kernel m=1 0.133→0.041（3.2×）、m=3 1.448→0.126（11.5×）、
  m=45 1.1×、m=180 1.0×；`analyze(known)` 1.513→**0.148（10.2×）**、`auto` 3.631→0.920、
  `scan_R` 2.047→0.747、`estimate_amp` 2.650→2.604（**没变快**，180 路本来已摊薄）。
- **验证**：`tests/test_kernel_golden.py`（13 项）+ `tests/golden/kernel_ref.json`
  （改动**前**冻结的 `p/pstd/mx/trace.X` sha256）。用哈希不用容差——混沌态 1 ulp 会被
  指数放大。算例矩阵在 `tools/kernel_cases.py`（测试/基准/重冻结共用，不许各写一套）。
  `py tools/bench_speed.py` 一条命令出速度表 + 逐位校验。
- 不做：numba/cython（未装）、多进程扫频（每任务 47 ms，Windows spawn ≈1.5 s/进程，
  串行 0.75 s 更快）、多线程（纯 float 循环持 GIL）、缩短瞬态（改论文口径）。
  并行轴本来就是**通道维**（`pstd_batch` 按 K×3 拼列，m=90 时 21 ms/路 vs 逐路 140 ms）。
- 文档：`00-总览/性能优化与基准.md`（+ html），`阅读路线.md` 有入口。

## 固件规格
- **Poincaré 插值权重必须是补角**：`frac` 是 DDS 溢出余量，权重 `(PH_INC−frac)/PH_INC`；
  写反会把周期态 pstd 从 3.2e-6 抬到 1.2e-2（混沌态只差 0.1%，只有 F=12 有分辨力）。
- **12 位小数的 pstd 地板 = 2.7e-3**（周期态，F=12；F=10 为 7.6e-3）。固件期望值一律
  取 `simulate_fixed_seq`，浮点只作旁证。
- **`u≡0` 不是 pstd 塌缩**：全零输入仍有内驱混沌（pstd 0.431），断线只能靠 `peak` 判。
- 门限分工：默认 `PSTD_TH=0.08`（Pfa≈0）；`0.347` 是 200 帧 H0 的 5% 分位等虚警门限，
  只能用于报 Pfa。覆盖率：三相位满覆盖需 A ≥ 0.0263（SNR ≥ −8.6 dB）。
- PC 耗时（0.15 s / auto 0.92 s / 估幅 +2.6 s）与 ESP32 的 8 μs/步估算（1.13 s）是
  两套口径，别混着引用。
